# 사과 바구니 실측 치수 교정

사용자가 바구니의 작은 크기·미세한 방향·픽셀 정규성을 재개방했다. 이전 원본/출력과 26개 배치는 보존하며 같은 바구니3개만 교정한다. 기존 `flat_prop(produce, .25)`는 원본 전체 높이를 물리 높이로 읽어 실제 bbox172×113을42×27화면픽셀로 만들었다. 별도Collider .6×.25×.45와 대응하지 않는다. 원본자동PP198×164 뒤 발생한 물리 환산 문제이며 PerfectPixel만으로 해결되지 않는다.

## 결정과 실패 조건

실측 카탈로그 `metric-catalog.json`이 미터 치수의 단일 기준이다. 상자는 실제 제품40×30×10cm, 사과 비교범위는 지름70~95mm다. 공통127px/m이면 구형사과의 화면 지름은8.89~12.065px다. 이 범위는 모든 품종을 제한하는 자연법칙이 아니며, 이번 사물 디자인의 비교 기준이다. 현재 원본의 가장 큰 두 사과가 이 범위와 크게 어긋나면 상자와 과일을 분리한 입력이 필요하다. bbox전체배수확대로 숨기지 않는다.

후보는 ①현재세로이미지확대 ②기존목재3면공통투영 ③빈상자+독립사과배치다. ①은사과까지과대해지고면기울기를못고쳐제외한다. 원본을유지하는②를최소실험하고, 표현된과일이허용크기/형태와맞지않으면③으로돌아간다. 표준평면 homography 근거와R/U좌표는 B35 README와같다. 뒤모서리는원본가림에따른추정값이며보이는점과구분한다. 사과는상판의paintedcontent로근사되며3D구체복원이아니다.

canonical은 X폭.4/Z깊이.3/Y목재높이.1의공유꼭짓점이다. 세부source좌표는별도랜드마크자료가소유한다. 원본PP는재실행하지않고공통면으로단일표본을만든다. 색과깊이는동일source/면소유,material은Point/무압축/mipmap없음,각Transform.scale은1이다. 변경할때마다png를임의비율로resize하는대신미터치수에서출력면적과픽셀수를계산한다. 동일너비/깊이를Collider에도반영하고과일포함높이는.2m보수체적이다. 위치와상판anchor는기존값그대로다.

실험증거는 `docs/artifacts/building35/tray-size-correction`에 보존한다. 기술 검사는 새asset alpha/깊이/공통PPU·입력점변환·실제Unity화면에 한정한다. 바구니Collider는 .6×.45→.4×.3으로작아지고위치고정이라기존지상동선은다시실행하지않는다. 이전소품확인3경로증거를재사용한다. 사용자의미술확인없이완성판으로승격하지않는다.
