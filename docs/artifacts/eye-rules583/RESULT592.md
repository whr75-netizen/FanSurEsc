## 구현과 첫 실패 수정

제품 변경은 `EyeFeature348.cs`, `EyeRenderer367.cs`, `EyeFeature348.compute` 주변에 한정했습니다. 590 구현 체크포인트는 `131c66d8dc59158b4b107c9f66b4d589a83eab1f`입니다.

1. 모델 원본24정점 눈 링에서 rest 눈 축으로 윗경계 chain을 고릅니다. 현재 변형 정점과 기존 바깥 .36/안쪽 .22 두께로 닫힌 ribbon을 만들고, 기존 CurveArea511 연속 합집합 면적을 재사용합니다. 작은 면적도 원본 알파로 제거하지 않습니다.
2. ROI의 각4×4 subcell에 기하 면적·같은 sample ray의 깊이·rest-u/v만 공급합니다. 후보 가림에는 기존 머리카락·눈썹·몸의 깊이/알파 경로와 기존 `N=floor(A+.5)`·순위를 유지합니다. 뒷면은 채우지 않습니다.
3. 선택된 속눈썹의 색은 현재 같은 눈 S3, 없으면 기존 같은 눈 template role6에서 공급합니다. 원본 알파는 색 공급에 쓰며 영역 존재·두께의 권위가 아닙니다. 기하 support sentinel4를 native UV/primitive/barycentric으로 위장하지 않습니다.
4. 첫 실제 R2의35쌍에서, 부분 곡선 면적이 있는 subcell 전체를 속눈썹으로 분류하던 탓에 선택되지 않은 곳의 홍채·흰자도 사라지는 회귀를 발견했습니다. 592는 **기존 Sample583을 원문 그대로 복원**하고 곡선 후보를 별도로 집계·선택합니다. 홍채·흰자는 곡선 후보가 실제 선택된 셀에서만 속눈썹으로 덮입니다. R2 실패와 R3 국소 확인은 별도 보존했습니다.

특정 좌표·포즈 예외, 최소1픽셀 강제, 이전 프레임 덮개, 원본 알파 형상 gate, 실패한587~589 GPU 필터·half·거대 면적 공급기는 추가하지 않았습니다. 새 고해상도 RT나 제품 CPU readback pass도 없습니다.
