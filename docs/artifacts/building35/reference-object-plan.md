**상태: 제안·미적용.** 2026-09-27. Unity, B34 원본 이미지, 카메라, 기존 씬은 이 작업에서 변경하지 않았습니다. 사용자가 B34의 각도와 물품 부족을 거부하셨으므로, 특정 두 자산을 임의로 합격 처리하지 않았습니다. 이 문서는 참고 화면의 관찰과 새 상가에 대한 설계 제안을 분리합니다.

## 2. 현재 10×8m에서 사용할 역할 템플릿

**생활식품 소형 상가**를 제안합니다. 기존 계산대·벽 선반 두 곳·낮은 진열섬·창고 선반을 유지하고, 냉장 판매/직원 준비/청소/입구 보조 기능을 추가합니다. 낚시점의 낚싯대와 생선을 그대로 복사해 식품점에 넣지 않습니다. 참조하는 것은 역할과 지지 관계, 높이별 정보량입니다.

| 구역 | 큰 시설 | 작은 물품 | 비워 둘 공간 |
|---|---|---|---|
| 계산 | 기존 계산대 | 등록기, 직원 장부, 소형 상품 바구니 | 고객 앞 1.3m, 직원 뒤 1.3m의 기존 사용 영역 |
| 벽 판매 | 기존 서/북측 선반 | 음료, 포장 식품, 병/용기 묶음 | 기존 각 선반의 앞 사용 영역 |
| 중앙 판매 | 기존 낮은 진열섬 | 제철 농산물과 같은 산지 보존 식품 두 묶음 | 서쪽 고객 접근면. 사방 통행이 된다고 주장하지 않음 |
| 냉장 판매 | 동쪽 벽 냉장장 | 냉장 음료는 냉장장 자산의 구성 요소 | 서쪽 접근점과 중앙에서 이어지는 통로 |
| 재고 | 기존 북동쪽 재고 선반 | 미개봉 상자/보충 용기 | 기존 창고 문과 적재·반출 영역 |
| 직원 작업 | 새 준비대와 청소 수납장 | 하부 단일 쓰레기통, 벽 걸이 빗자루 | 북쪽 작업 접근점 |
| 입구/정보 | 장바구니 묶음, 평면 발판 | 직원 쪽 시계, 후면 벽등 | 중앙 2m 입구와 1.5m 주통로 |

이는 **8개 큰 시설 + 2개 바닥 보조품 + 15개 지지면/벽/수납 내부 소품 = 25개 배치 노드**입니다. 상품 묶음 하나를 하나의 저작 자산으로 세었으며, 병 하나하나를 세어 수량만 부풀리지 않았습니다. 구현 시 기존 이미지 안에 이미 그려진 물품을 다시 올려놓아 이중 표현하지 않습니다.

기존 다섯 시설의 footprint와 몸체 높이를 보존했습니다. 등록기는 1m 계산대 위의 별도 소품이므로, 등록기까지 포함한 높이로 계산대 몸체 전체를 키우지 않습니다. 선반 내용물의 Y 좌표는 **그 높이에 실제 선반 판재가 있는 템플릿**을 제작할 때만 유효합니다. 현 원본 그림에 해당 받침면이 있다고 검증한 것이 아닙니다.

계산대/선반 원본에 상품·등록기가 이미 포함되어 있으면 먼저 다음 중 하나를 명시합니다.

1. 빈 지지체와 독립 소품으로 저작하여 표의 개별 노드를 사용합니다.
2. 통합 자산을 유지하면 내부 소품을 별도 인스턴스로 겹쳐 추가하지 않고, 인스턴스 수를 실제 값으로 줄입니다.

한 원본에서 가려진 빈 선반 재료를 얻을 수 없는데, AI가 그 부분을 자동으로 정확히 복원했다고 처리하지 않습니다. 전체 맵 이미지를 한 장 만들고 그것을 실내 게임 오브젝트의 대체물로 쓰지도 않습니다.

## 4. 동선 계산과 그 한계

이번에 실행한 **정적 계획 계산** 결과입니다.

- 신규 바닥 장애물은 냉장장·준비대·청소 수납장·장바구니의 4개입니다.
- 기존 5개 시설/벽/칸막이와 신규 4개가 겹친 경우 0개, 기존 주통로/6개 시설 사용 영역을 침범한 경우 0개입니다.
- B32와 같은 0.1m 격자, 4방향 BFS, Player 반지름 0.5m + 설계 여유 0.1m + 셀 반대각선 약 0.07071m를 사용했습니다. 중심과 장애물 사이 거리가 0.67071m보다 큰 셀만 통행 후보입니다.
- 입구에서 **기존 접근점 6개와 신규 접근점 4개 모두 연결**되었습니다. 자유 셀 2,898개 모두 입구 연결 성분에 속했습니다.
- 12개 가구 지지 소품의 XZ footprint가 해당 지지체 범위에 포함됩니다. 이는 원본 그림의 shelf 높이나 깊이가 맞는다는 증거가 아닙니다.

상세 값은 `object-plan.json.validation`에 있습니다. 장바구니·준비대·청소 수납장 접근점의 최근접 장애물 거리는 약 0.675m로, 이번 보수적 격자 조건의 여유가 큽지는 않습니다. 실제 Collider나 문짝이 더 돌출되면 재계산해야 합니다. 문짝 회전, 실제 Player 이동, 상호작용, 이미지 가림, 실제 Unity 벽의 일치는 아직 검사하지 않았습니다. BFS 성공을 Play Mode 검증이나 미술 합격으로 보고하지 않습니다.

## 5. 각도 문제를 물품 추가로 숨기지 않는 제작 경계

각도 해결은 별도 [면별 투영 계약 후보](projection-contract-proposal.md)를 따릅니다. 이 물품 계획은 그 실험을 통과시켰다는 문서가 아닙니다.

- 프로젝트 목표 pitch 30°/local yaw 45° 직교 투영에서 바닥축 화면 기울기는 ±0.5입니다. **화면 사선 30°와 카메라 pitch 30°를 혼동하지 않습니다.**
- 같은 facing/치수의 시설은 동일한 공유 틀에서 색 면과 깊이 면을 함께 결정합니다. bbox가 들어가는 것, 좌우 반전하는 것만으로 원본 내부 면의 기울기가 일치하지는 않습니다.
- B34의 127 PPU나 181 PPU를 이 계획의 승인값으로 사용하지 않습니다. 공통 세계 픽셀 밀도는 입력 특징 보존과 물리 비례를 동시에 만족하는 값이 아직 정해져야 합니다.
- 원본 PerfectPixel 자동 정규화는 원본의 샘플 격자를 정하는 단계입니다. 모든 물체의 물리 폭이나 픽셀 밀도를 같게 만들지는 않습니다. PNG를 강제 동일 크기로 축소하여 시설 슬롯에 끼우지 않습니다.
- 벽/지지체/소품 각각의 source 면, 공유 좌표, 지원 면, 가림 깊이를 함께 기록합니다. 없는 면이나 맞지 않는 표면이 확인되면 입력 단계로 반환합니다.

제작 순서는 **상가 역할/배치 계약 → 실제 투영에 맞는 빈 지지체와 방향 두 종류의 소규모 실험 → 공통 픽셀 밀도/특징 보존 → 해당 지지체에 맞는 물품 저작 → 고정 좌표 조립 → 실제 카메라에서 전체 실내 확인**입니다. 상품을 먼저 대량 생성한 후 가구에 임의 크기로 맞추지 않습니다.

## 6. 직원 화장실과 완성 범위

직원 화장실은 이번 25개 배치 후보에 **아직 없습니다**. 참고 그림에서도 확인하지 못했고, 현재 B32 창고의 선반과 사용 영역을 유지하며 독립 화장실 구획까지 넣을 수 있다는 계산도 하지 않았습니다.

화장실이 이 건물의 필수 프로그램이면 별도 방, 출입문, 변기/세면대 사용 공간, 창고 기능 이전을 함께 설계해야 합니다. 창고 한쪽에 변기 그림만 추가하여 화장실로 세지 않습니다. 기존 통로 보존 조건을 바꿔야 한다면 그 변경 원인과 새 배치를 명시하고 같은 동선 계산을 다시 수행합니다. 그러므로 이 문서는 건물 전체의 현실 설비를 모두 완성했다는 보고가 아닙니다.

## 7. 인수인계

수정한 파일은 이 문서와 `object-plan.json` 두 개뿐입니다. 정적 배치 계산 외에 게임/Unity 실행은 하지 않았습니다. 다음 제작자는 JSON의 source 관찰/추론, 지지체 포함 조건, 미결 화장실, projection gate를 그대로 읽고 실제 작업 대상으로 변환해야 합니다. 다른 두 개가 맞다는 사용자 표현에서 임의로 합격 자산 두 개를 선택하지 않습니다.
