# 586 실제 GPU 필터와 면적 입력의 분리

제품 면적 입력은 교체하지 않았다. 소스420b3ae와 두 옵션 기본 OFF를 유지했다. 이번 변경은 런타임에서 참조하지 않는 GPU 샘플러 진단 에셋 한 개와 오프라인 계산·검증 기록이다. 새 실제 회전 영상은 없다. 기존583 영상은 미해결 출몰이 남은 이전 후보 결과다.

## 필터에서 실제 확인한 차이

런타임은 Direct3D11 / RTX2080Ti이며 실제 텍스처는 1밉, Bilinear, anisoLevel1, Repeat다. 사용자 QualitySettings는 ForceEnable이다. UV 변환은 (1,1,0,0), UV 애니메이션0, 알파 cutoff0.5다. 설정과 텍스처를 바꾸지 않았다.

저장9포즈의 실제 UV 23,986표본에서 원래 알파와 밉0 SampleLevel의 최대 차이는0.3877165였다. 실제 미분값에 가까운 입력을 전달한 SampleGrad는 최대0.0083009였다. 예를 들어5번 사례의 가운데 포즈, 논리셀(230,49), 표본k9, 아이라인 지원에서는 원래 알파0.5017624, SampleGrad0.50176239, 밉0은0.88947892였다. 밉이 하나라는 사실만으로 필터를 bilinear 한 점으로 취급할 수 없다.

같은 primitive의 실제 2×2 UV 차분을11,490축, 충분한 실제 UV의 affine fit을11,616축에 사용했다. 나머지는 투영 삼각형 미분값이며 실제 shader ddx를 읽은 값으로 취급하지 않았다. 한 포즈의 실제 cropProjection 경로를 조회하여 잔여 불일치 하나를 더 줄였지만, 알파 오차0.001 초과15표본이 남는다. 따라서 GPU 전체와 비트 동일한 연속 알파 함수를 확보했다고 하지 않는다. 단일 포즈 조회의 눈 visible/intrinsic260기록은 이전 입력과 같았다.

## 출력 수를 바꾸는 면적 차이

기존 래스터에서 보이지 않았던 뒤쪽 삼각형까지 포함해 같은 시선의 알파 통과·깊이 소유권을 다시 계산했다. 원래4×4의 기하 후보 2896점에서 기존 가중치와 모두 일치했다. 이후32/64/128분할 및128분할 시작점 이동(.25,.25)을 비교했다. 표본 밀도를 올릴 때 텍스처 미분값은 원래4×4 래스터의 폭으로 고정했다. 단순 고해상도 재래스터처럼 필터 폭까지 바꾸지 않았다.

계산한 면적은 원래 아이라인 텍셀 넓이가 아니라 기존 Classify의 rest-head 곡선 띠가 같은 눈의 가시 지원을 갖는 넓이다. 이전585의 삼각형/가림 오라클을 재사용했다. 헤어는 실제 입력인 기존 HairMETA를 유지했고, 눈썹과 몸 가림도 같은 시선으로 처리했다. 겹친 삼각형을 면적에 중복 합산하지 않았다.

단위는 논리셀²다. 현재1논리셀은2×2화면 픽셀이다. 표의 프레임은 각3포즈 조회 내부 인덱스이며, 사건2/5/16은583 발췌 영상의 가운데 프레임이다.

모든 검사 밀도와 격자 이동에서 SampleGrad, SampleLevel0, 수동 bilinear의 면적과 출력 수가 서로 같았다. 개별 BLEND 알파 차이는 크지만 이9포즈의 최종 선 지지 면적에는 영향을 주지 않았다. 비교 기준의 출력 수는000 / 000 / 111이며 현재4×4는010 / 010 / 101이다. 실제 면적은 변하나 확인한 포즈에서는0.5를 넘나들지 않는다.

오차 추정은 `2×max(|A128−A64|, |A128shift−A128|)`다. 최대 0.0067139셀²이고 모든0.5 경계 거리는 추정 오차의3배보다 크다. **엄밀한 오차 상한은 아니다.** 실제 shader의 helper-lane 미분값을 모든 연속 좌표에서 읽은 것도 아니다. 따라서 이 결과는 명시한 미분값의 실제 GPU 샘플러 기준에 대한 수렴 근거이며, 모든 하드웨어의 연속 면적 증명이 아니다. 이 한계와 이전585의 bilinear 상한 증명 범위를 혼동하지 않는다.

## 제품 교체와 비용

면적 입력 오차가 세 사건의 출력 수 반전에 기여한다는 근거는 강화됐다. 반올림·순위·홍채·가림을 바꾸거나 최소1픽셀을 강제할 이유는 확인되지 않았다. 다만 현재 EyeFeature348 인터페이스는4×4 원시 표본만 전달하며, 손실된 연속 면적을 이 표만으로 복원할 수 없다. 원본 투영 삼각형/rest/UV 및 현재 가림으로 A를 공급하는 구현이 필요하다.

이번 오프라인 ray 조회·CPU 선택·GPU 필터 적분을 제품에 그대로 넣지 않았다.128분할의 GPU 조회와 readback만9포즈 합계 1.280초다. 여기에 기하 후보 준비와 CPU 적분도 별도로 든다. 이는 캡처나 전체 렌더 시간도, Player FPS 측정도 아니다. 실시간 적합성이 확인된 A 공급 경로는 아직 없다. 고정 고밀도 표본 수만 늘린 런타임 후보를 추가하지 않았다.

새 실제 회전/세 방향 회귀는 실행하지 않았다. 기존 정상 축소·완전 가림 반례와 홍채24/속눈썹846/세 방향1,136기록은 원래 소스 해시가 같아 보존하며 새 검증으로 세지 않는다. 내부선 팔레트3, 일반 실행 성능·할당, 손 문제는 별도다.

## 복원과 저장

최종 공식 조회로 Edit clean, Play/홍채/속눈썹/Head/Clothes/자동 입력 OFF, inputBytes0, captureDelta0, backgroundfalse와 Console Error/Exception/Assert0을 확인했다. 사용자 QualitySettings/TimeManager 해시도 같았다. 진단 compute에는 부호 있는 정수 나머지 연산 관련 경고2개가 있으며, 첫 호출은 경고 때문에 MCP가 부분 실행 오류를 반환했다. 완료 마커와7개 출력으로 실제 완료를 확인했고 같은 호출을 중복 실행하지 않았다. 후속 독립 배치는 성공했다.

원본9포즈와23,986표본의 필터 대조는 로컬에 보존했다. 새 고밀도 조회의 재생성 가능한 임시 이진 파일만 소비 완료 후 크기·SHA256 목록을 남기고 정리했다. 기존 캡처·D보관본·사용자 파일은 건드리지 않았다. 새 전신 이미지0, P드라이브 접근0, Library403 재시도0이다.

다음 의존성은 **원래 연속 영역에서 A를 공급하는 실시간 경로**다. 이번 필터 분리를 완료한 사실과 제품 A 교체·실제 애니메이션 품질의 미완료를 구분한다.
