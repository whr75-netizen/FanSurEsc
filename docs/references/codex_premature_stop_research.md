# Codex의 작업 중단과 중간 질문 처리에 관한 공개 보고 조사

확인일: 2026-09-20. 조사 범위는 OpenAI 공식 문서와 `openai/codex` 공개 이슈다. GitHub 이슈의 작성자 관찰과 OpenAI의 공식 설명을 구분한다. 아래 상태는 확인일에 가져온 공개 페이지 기준이며, 제품 전체의 해결 여부를 뜻하지 않는다.

## 결론

큰 작업 도중 사용자가 덧붙인 질문을 새 작업으로 해석하고, 그 질문에만 답한 뒤 원래 작업을 멈춘다는 공개 보고가 있다. 특히 2026년 2월의 [이슈 #11062](https://github.com/openai/codex/issues/11062)는 이번에 지적된 대화 흐름과 매우 가깝다. 별도로 진행 보고 뒤 종료되는 사례와 자동 컨텍스트 압축 뒤 작업 진도를 잃는 사례도 존재한다. 이 세 현상을 같은 원인으로 단정할 근거는 없다.

이번 대화에서 직접 확인된 실패는 진행 중이던 구현을 유지해야 하는데도 중간 질문을 별도의 읽기 전용 요청으로 취급해 최종 응답으로 종료한 판단이다. 컨텍스트 한도 도달, 압축 실패, 서버 장애 또는 특정 모델의 결함이 이 판단을 일으켰는지는 확인하지 않았다. 사용자 측의 실제 호스트 로그와 중단 시점의 이벤트를 조사하지 않았으므로, 공개 이슈가 있다는 사실을 이번 사건의 원인 증거로 대신할 수 없다.

OpenAI가 관리하는 저장소에 게시되고 라벨이 붙었다는 사실만으로 OpenAI가 각 보고의 모든 원인 분석을 인정했다고 표현하지 않는다. GitHub의 활동·댓글 일부는 검색 도구에서 노출되지 않을 수 있으므로, 위의 “확인하지 못함”은 모든 비공개 조사나 모든 댓글이 없다는 뜻도 아니다.

## 공식 문서가 설명하는 기대 동작

[Long-running work](https://learn.chatgpt.com/docs/long-running-work)는 관련 작업을 같은 대화에 유지하고, 목표·제약·검증 기준을 명확히 하도록 설명한다. 진행 중인 목표에 후속 메시지로 정보를 추가하거나 제약을 조정할 수 있고, CLI에서는 상태 요약을 받은 뒤 작업을 계속하는 흐름도 안내한다. 따라서 중간 질문이나 상태 확인 자체를 원래 목표의 자동 취소로 보는 해석은 이 안내와 맞지 않는다. 이는 기대하는 사용 흐름에 관한 공식 설명이며, 모든 실행에서 중단이 발생하지 않는다는 보증은 아니다.

[Best practices](https://learn.chatgpt.com/guides/best-practices)는 긴 대화가 컨텍스트·결정·작업 이력을 누적하며, Codex가 대화를 자동 압축한다고 설명한다. 또한 같은 문제라면 같은 대화를 유지하되, 프로젝트 전체를 하나의 무한히 긴 대화에 넣기보다 하나의 일관된 결과 단위로 작업을 구성하도록 권장한다. 컨텍스트 관리가 품질에 영향을 준다는 근거는 되지만, 특정 중단을 컨텍스트 용량만으로 설명하는 근거는 아니다.

## 이번 작업에서 적용할 예방 원칙

다음은 제품의 수정 완료 주장이나 검증된 만능 해결책이 아니라, 확인된 실패를 줄이기 위한 작업 운영 제안이다. 현재 프로젝트의 기존 WorkLoop와 상태 문서를 재사용하며 별도의 평행 관리 체계를 추가하지 않는다.

1. 원래 산출물과 완료 조건을 작업의 기준으로 유지한다. 중간 질문에 답한 뒤에는 기존에 허용된 다음 구현·검증을 계속한다. 사용자가 명시적으로 취소하거나 양립 불가능한 새 목표를 제시했을 때만 목표를 교체한다.
2. 진행 보고와 최종 종료를 구분한다. 다음 행동을 말할 수 있고 권한 범위 안에서 실행할 수 있다면 보고 직후 실제 행동으로 이어 간다. 완료, 실제 차단, 사용자 중단 요청을 종료 사유와 구별해 기록한다.
3. 압축 전후에는 현재 목표, 완료된 변경, 남은 완료 조건, 다음 행동, 사용자 정정을 짧은 상태로 유지한다. 이미 확인한 자료를 모두 다시 읽는 대신 이 상태와 현재 diff를 재동기화한다.
4. 재발 조사는 한 사건의 좁은 시간대만 대상으로 한다. 마지막 사용자 메시지, 마지막 도구 실행, 최종 응답 여부, 압축 이벤트 여부, 연결 오류 여부를 서로 구분한다. 전체 로그를 공개하지 않고 비밀·프로젝트 데이터를 제거한 최소 재현 정보만 마련한다.

현재 문서만으로는 컨텍스트 창 크기를 임의로 늘리거나, 자동 압축을 끄거나, 모델을 바꾸는 방법이 이번 증상의 해결책이라고 권장할 수 없다. 원인 진단 없이 “계속”을 자동 반복하는 방식도 정상 완료·승인 대기·실제 차단을 구분하지 못하므로 채택하지 않는다.

## 검증과 미확인

- 검증: 위 다섯 출처의 실제 페이지를 열어 증상, 게시일, 공개 상태, 공식 안내를 확인했다. 검색 요약만으로 결론을 내리지 않았다.
- 미확인: 이번 세션의 서버 내부 상태, 중단 당시 토큰 사용량, 압축 실행 여부, 모델별 재현율, 제품 수정 배포 여부.
- 변경 범위: 이 조사 문서만 작성했다. Codex 설정, 프로젝트 지침, Unity 코드·에셋은 변경하지 않았다.
