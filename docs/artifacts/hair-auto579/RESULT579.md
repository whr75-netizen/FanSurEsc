# 579 자동 방향 입력과 실제 회전 결과

런타임 자동 입력 생성·교체를 기본 OFF 후보로 연결했다. 기존 외부 파일 생성/주입이 없어도 실제 변형 헤어 메시에서 폐곡선과 원본 anchor를 만들고 기존 577 영역·채움·가림 경로를 사용한다. **전체 회전 품질은 미통과**다. 100° 포즈의 얼굴색/소유권 불일치가 눈 합성에서 재현되어 방향 확대를 보류했다.

불투명·양면 Hair와 직교 카메라라는 기존 재질/가림 계약에 한정한다. 같은 뷰의 실제 Walk 변형에는 anchor를 갱신한다. 루트/카메라 뷰가 그대로인데 머리뼈만 크게 회전하여 차트 위상이 바뀌는 경우까지 자동 유효성을 증명하지 않았다. 원본 삼각형 중심 래스터를 복사하는 마스크가 아니며, 색/눈/손/영역 선택 비용이나 가림 epsilon은 변경하지 않았다. 0.14/0.1875는 논리 픽셀 좌표의 기존 디자인 상수이며, 해상도에서 유일하게 유도된 연구 공식이라고 주장하지 않는다.

## 실제 증거

- 저장 참조 yaw80/170/260에서 원본 경계 532/608/595점 → 스타일 94/92/114점, 기존 결과와 선택 마스크 차이 0. 최초 float 경계에서 원본 삼각형 재탐색이 실패한 6/12/9점은 출처 전달로 대체했다. anchor 재투영 최대 오차 약 0.0000076px, 비음수·합 1 계약 통과.
- 실제 Walk와 `RotateTowards(90°/s, 1/60s)`의 회전 비교 14쌍: 80° → 96.47345°. 다음 97.97345°·normalizedTime 1.45000327에서 **기존 고정 yaw80 기준 입력**이 실패했다. 자동 쪽은 그 프레임에 미실행이다. 처음부터 정상 포즈를 정지한 검증으로 대체하지 않았다.
- 실패 계산: `HairRegions574.Build`의 `a = root + hole - union`. hole-ring:2, 셀 (233,45), root=0.9982207, hole=0, union=0.997845 → a=0.000375688076; 허용 상한 min(root,hole)+0.000002를 넘는다. 보호 임계값을 완화하지 않았다. 같은 저장 실제 메시로 현재 입력을 생성하면 3곡선·91점, 선택 527셀로 통과한다.
- 별도의 **제품 기본 헤어 대 자동 후보** 실제 비교 8쌍: 96.47345° → 100° → 96.47345°. 동일한 실패 각도·Walk 시간의 자동 렌더도 실제 완료했다. 두 비교의 왼쪽 기준은 서로 다르며 GIF에 각각 표시했다. 두 번째는 577 고정 차트 비교가 아니다. Clothes547은 양쪽 동일, Body0 후보 OFF.
- 두 구간의 카메라·시간·포즈 일치, 머리 ROI 밖 전신 RGB 차이 0, 후보 경계 밖 머리 출력 0, 단일 소유권 일치. 첫 구간 얼굴 coverage 변화 23표본, 두 번째 64표본은 추가 머리의 source-ray 증거가 모두 있고 앞의 불투명 얼굴을 덮은 판정 0. 모든 destination/world 가림까지 증명한 수치는 아니다.
- 눈 intrinsic 입력 차이 0. 첫 구간 visible eye 버퍼 차이 2표본, 두 번째 0. 578의 속눈썹 관찰점은 이전 저장 81프레임에서 한 프레임 ABA가 없었으나 모든 눈의 시간 품질 합격을 뜻하지 않는다.

## 새로 확인한 품질 차단

8쌍 중 같은 비헤어 meta에서 RGB가 달라진 2표본을 보존했다. 프레임 4의 옷 (211,57)은 정확한 0.55 선색 전환이다. 실제 OwnerLines333 audit는 이 포즈에서 별도 수집하지 않아 정상 디자인 여부를 단정하지 않는다.

프레임 3의 얼굴 (227,48)은 정상 가림이라고 처리할 수 없다. 동일 포즈 100°·Walk phase 0.475003362에서 한 번 최소 재현했다. head 좌표 (230,48)의 prepared/postLine은 양쪽 피부색 (0.9609375,0.7871094,0.628417969)이고 owner=4, depth=13.7673817로 같다. 뒤 `EyeRenderer367.Dispatch → EyeFeature348.Evaluate/Unpack/Merge`의 eyeOutput에서 후보만 (0.07405918,0.0846116245,0.141855076)로 바뀐다. 최종 owner/meta와 눈 가시성은 같다. MainToHead/EyesToMain 이후 최종에도 그대로 전달된다. 최초 관측 차이는 눈 resolve의 색 출력이며 Base/Backing의 원본 RGB/meta 중 어느 입력 분기에서 잘못 결합됐는지 추가 좁은 조회가 남는다. 이 단계에 임의 피부색/새 필터/가림 패치를 추가하지 않았다.

따라서 좁은 회전 **실행은 완료**, 전이 전체 품질은 **미통과**다. 더 넓은 80↔170↔260 전이와 전체 루프를 새로 촬영하지 않았다.

## 비용·전달·복원

자동 생성의 관측 최대는 약 365ms이고 기존 패킷 비용도 별도 남아 있어 실시간 채택 기준에 이르지 않았다. 정확한 중앙값/P95는 QUALITY579.json에 생성·키·Build·영역·패킷별로 분리했다. 생성 시간은 동일 revision의 재사용 행을 제외한 호출 표본으로 집계했다. 진단 캡처 중 CPU span이며 GPU 시간이나 Player FPS가 아니다. 이번에는 할당량 측정/최적화를 하지 않았다.

전신 원본 960×544 PNG는 모두 작업공간에 유지한다. 전달 GIF/WebP만 모든 캐릭터 셀을 포함하는 공통 crop을 사용하며 재확대하지 않는다. 14프레임 GIF 346,089B/WebP 195,916B, 8프레임 GIF 218,260B/WebP 112,162B. 모든 프레임을 보존했다. WebP는 233ms/133ms 무손실, GIF는 10ms 단위 제한으로 230ms/130ms다. 짧은 구간 끝에서 다시 재생되는 연결은 실제 운동 전이로 검증한 것이 아니다. 전체 Walk GIF로 표시하지 않는다.
