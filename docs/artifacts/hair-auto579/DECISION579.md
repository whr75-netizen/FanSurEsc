# 579 자동 시점 입력과 연속 회전 검증

578의 생성기 재사용은 검증 스크립트가 실제 메시를 추출하고 외부 생성기를 호출한 뒤 `SetCurveInput511`에 파일을 주입하는 경로다. `Indices511`에는 시점 유효성 검사·재생성·교체 호출이 없으며 모델 서명만 확인한다.

이번 결과 목표는 수동 방향 파일 없이 같은 폐곡선·원본 primitive/barycentric anchor 계약을 만드는 별도 OFF 경로와 실제 연속 회전의 좁은 구간 검증이다. 원본 코드·자산·577/578 증거·기본 OFF·사용자 설정은 보존한다. 시간 필터, 방향별 예외, 손·명암·성능 최적화는 제외한다.

## 고정한 입력과 계산 계약

현재 변형 헤어 메시 로컬 좌표 → 기존 `TransformPoint`의 월드 좌표 → `Full319View335.Project`의 480×272 논리 좌표 → 기존 벡터 합집합 → 기존511의 영역·둘레 비용(.14)과 폐곡선 오차(.1875 논리px) 및 교차 검증 → 원본 삼각형·무게중심 anchor → 기존577 선택·색/UV 공급·가림/합성이다. 셀 중심 마스크나 RGB로 source를 재생성하지 않는다. 현재 모델의 헤어 알파가 불투명이라는 기존 근거를 사용하며, 일반 알파 카드까지 검증됐다고 확장하지 않는다.

재사용 후보는 이미 Python `vector_union`을 포팅한 `ClosedRegion524.Build`다. 먼저 같은 저장 기준 입력3개에서 원본 경계와 기존 regularize 결과가 기존 생성기와 동등한지 한 번 비교한다. 수치 비교는 기존 anchor의 재투영 허용 오차 .0005 논리px와 동일 선택 마스크를 기준으로 하며, 디자인 계수는 조정하지 않는다. 실패하면 최초 차이 단계와 숫자를 기록하고 새로운 커널·패널티를 쌓지 않는다.

사전 비교가 통과하면 기존 입력 준비 책임만 C# 런타임에 연결한다. 상대 모델/카메라 방향과 투영의 실제 변경에서 재생성하고, 각도 구간 표나 수동 yaw 임계값은 두지 않는다. 입력은 한 현재 차트와 그 소스 서명만 유지하며 전역 상태 bank를 만들지 않는다. 기존 파일 입력은 OFF 경로에서 보존한다. 모델/카메라/알파 조건이 맞지 않으면 명시 실패로 처리한다.

## 실제 검증

기존 검증뷰 사이의 좁은 회전 구간을 실제 Walk와 동시에 매 프레임 `RotateTowards`로 진행한다. 한 포즈의 각도 순간이동이나 이미지 보간을 애니메이션 검증으로 쓰지 않는다. 매 프레임 회전각·포즈·시간·입력 차트 변경과 실제 결과를 연결한다. 외곽선·양의 끝·음의 틈·눈 가림의 반복 출몰을 구분한다. 578의15번 약한 속눈썹 가림 시점 차이는 원인 분류만 완료됐으며 디자인 품질의 자동 통과가 아니다.

최소 구간 통과 후에만 범위를 확대한다. 기존 yaw80/170/260 입력과 실제 결과는 회귀 기준으로 유지한다. 현재 packet 비용과 미세 명암은 별도 미해결로 남긴다.
