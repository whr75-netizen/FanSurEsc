# 577 — 원본 음의 영역과 픽셀 선택·검사 영역의 일치

기준 commit은 `0e52a95`이며, 기준 전체 코드가 모든 방향에서 정상이라는 가정은 하지 않았습니다. 576에서 확인한 반대 옆모습 yaw260의 42번 실패 입력을 재사용했습니다. 수식·저장 입력 대조와 실제 애니메이션 검증은 구분합니다.

## 1. 확인된 원인과 수학적 계산

42번의 첫 위반 셀은 head 논리좌표 (219,48)입니다. 원본 열린 음의 영역 면적은 0.6667775819셀², 허용 narrow-cap 면적은 0.3777043188셀²로, 0.2890732631셀²를 초과합니다. 원본 연결 영역의 폭은 3.6821105921px, 면적은 19.3945932518셀²입니다. 폭 2 논리픽셀의 기존 큰 틈 보호 기준을 바꾸지 않았습니다.

초기 가설과 달리 내부 FILL이 입구를 막은 것이 아닙니다. **기준 signed 선택 P에서 이미 네 음의 셀이 4연결 외부와 단절**돼 있습니다. P는 실제 42번 OFF 마스크와 정확히 일치합니다. 후속 envelope cut이 추가한 10셀은 다른 위치이며, 이를 빼도 입구가 열리지 않습니다.

원본 가지 그룹은 면적 0.5를 넘는 셀을 8이웃으로 묶고, 외부/영역 채움은 4연결을 사용했습니다. 두 empty 셀이 대각선에서 닿는 것으로 그룹은 유지되지만 4연결 통로는 없습니다. Exterior 뒤 이 네 셀이 머리 채움 대상이 되어 큰 가르마 보호식이 정당하게 거부했습니다.

셀을 머리에서 틈으로 바꾸는 기존 비용 차이는 다음과 같습니다. 계수·면적 목적식을 새로 맞추지 않았습니다.

`ΔE = (2A − 1) + Σ βij · (현재 이웃이 머리면 +1, 틈이면 −1)`

`βcardinal = BoundaryCost × .58578644`, `βdiagonal = BoundaryCost × .29289322`, 기존 `BoundaryCost=.14`.

싼 셀을 무조건 비우면 원본의 양의 구분 형태를 지우게 됩니다. 따라서 원본 span이 같은 셀 내부에서 실제로 이어지고 공유 면을 통과하는 후보만 비용 비교에 넣었습니다. 원본 기하 접촉의 기존 수치 허용오차 1e-12를 사용하며 새로운 픽셀 미학 임계값을 추가하지 않았습니다. 좌표들은 이 사건의 계산 결과이며 제품 코드의 예외가 아닙니다.

## 2. 바꾼 두 소스의 책임

- `HeadRegion502.cs / SelectRegions543`: 기존 min-cut에 선택적 `requiredNegative` 입력을 추가했습니다. 필요한 음의 셀을 sink 제약으로 전달하며, 양/음 제약 충돌은 거부합니다. 제약 없는 호출의 결과는 유지합니다.
- `HairRegions574.cs / SourcePassages577, SourceCrosses577`: 큰 열린 원본 음의 영역에서 cap 밖이 닫힌 성분이 됐을 때, 원본의 셀 내부 연결과 기존 비용으로 단일 셀 통로를 선택합니다. 같은 음의 제약을 source 선택과 envelope 선택에 전달합니다. 여러 셀의 새 경로가 필요한 경우 임의 경로 탐색을 덧붙이지 않고 거부합니다.
- `HairRegions574.cs / KeepConnected577`: 후속 실제 전체 실행의 55번에서 확인한 검사 범위 오류를 정정했습니다. 이 수정은 픽셀 선택을 바꾸지 않습니다.

후처리 마스크, 과거 프레임 복사, 시간 평활, 새 RGB 보정, 깊이 바이어스, 모델/방향/프레임/좌표 예외를 추가하지 않았습니다. 내부 작은 틈 FILL과 외부 양의 형상·큰 틈 보호는 기존 책임을 유지합니다.

## 3. 55번 검사 범위 오류

첫 전체 실행은 0–54번 55쌍 완료 후 55번 ON에서 멈췄습니다. 같은 저장 입력은 이전576도 동일하게 거부했습니다. `hole-ring:1`의 폭은 2.0154041758px, visible KEEP는 9셀이며 8셀/1셀 두 조각입니다. **두 조각 모두 같은 envelope 바깥 배경과 연결**돼 있고 touches/sourceOpen/referenceOpen은 모두 true였습니다.

열린 영역을 머리로 잘라낸 조각만 세어 하나여야 한다고 검사한 것이 오류입니다. 열린 KEEP는 `visible ∪ !envelope`의 4연결 성분이 하나인지 검사합니다. 닫힌 KEEP는 visible 자체가 하나여야 하며, 기존 외부 접촉 조건도 유지합니다. 부유 내부 조각·서로 끊긴 닫힌 영역·빈 KEEP는 계속 거부합니다. 특정 조각 수를 허용하거나 보호 임계값을 완화한 것이 아닙니다.

저장55 및 유효 외부 조각/부유 내부 거부/닫힌 단일 영역/끊긴 닫힌 영역 거부/빈 KEEP 거부 반례가 통과했습니다. 실제 제품 컴파일 후 저장55 선택 마스크도 후보와 정확히 일치했습니다.
