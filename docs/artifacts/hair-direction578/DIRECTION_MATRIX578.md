# 578 헤어 방향 검증 범위

577 소스와 사용자 설정을 보존하며, 새 방향에 같은 일반 파이프라인을 적용하는 검증이다. 방향별 렌더 분기나 임계값은 추가하지 않는다.

## 실제 입력과 검증 범위

| 방향 | 입력 준비 | 실제 애니메이션 | 현재 판정 |
|---|---|---|---|
| yaw80, 기준 옆모습 | 기존 리소스: 3개 폐곡선, 94개 지속 anchor | 575 전체 81쌍. 577 저장 81입력 회귀 및 실제 71–73번 | 해당 입력·카메라에서 통과 |
| yaw260, 반대 옆모습 | 같은 자동 생성기에서 준비한 2개 폐곡선, 114개 anchor | 577 전체 81쌍 | 해당 입력·카메라에서 통과 |
| yaw170, 정면에 가까운 새 방향 | 실제 Walk70에서 자동 생성: 2개 폐곡선·92개 anchor | 578 국소 5쌍 후 전체 81쌍 | 해당 입력·카메라에서 형태 검증 완료, 속눈썹 가림 시점 1셀 차이 기록 |
| 나머지 회전각·회전 중 전이 | 준비된 자동 선택/재생성 계약 없음 | 이번 일반 헤어 경로의 유효 검증 없음 | 지원 완료로 주장하지 않음 |

이 카메라의 캐릭터→카메라 수평각은 실제 조회에서 168.9183°였다. 처음 후보였던 yaw0을 정면이라고 부르지 않는다. yaw170을 정면에 가까운 검증 입력으로 선택했다. 화면 방향과 캐릭터 좌우의 절대 명칭은 이 표에서 임의로 만들지 않는다.

`PlayerMovement.UpdateFacingDirection`은 `LookRotation(inputDirection)`과 `RotateTowards`를 사용하므로, 이동 방향은 고정된 두 옆모습이나 여덟 각도로 한정되지 않는다. 그러나 헤어 입력 어댑터가 그 모든 각도를 이미 지원하는 것은 아니다.

## 현재 자동화 계약과 빈 부분

1. 실제 변형 헤어 메시·원본 UV·토폴로지/바인드 해시·카메라 투영을 기준 포즈에서 추출한다.
2. 기존 `compile_curve511.py`가 원본 삼각형 투영의 벡터 합집합, 닫힌 영역 단순화, 자기교차 검증, 원본 삼각형/무게중심 anchor 바인딩을 자동 수행한다. 손으로 경계점을 편집하지 않는다.
3. `HeadRegion502.SetCurveInput511`에 준비한 불변 입력을 전달한다. `HeadCurve511.Indices511`은 모델 토폴로지/UV/bind 서명을 검사한다.
4. 매 포즈 실제 스킨 변형에서 anchor를 갱신하고 같은 영역 선택→패킷→기존 가림/합성으로 렌더한다.

현재 어댑터에는 시점·가시성 변화에 따른 입력 차트 유효성 검사와 차트 자동 생성/교체가 없다. 모델 서명 일치만으로 시점 적합성을 증명할 수 없다. 이번 방향도 기준 포즈 추출→생성기 호출→입력 전달이라는 검증 도구 조율이 필요하다. 이는 수동 좌표 저작과 다르지만, 제품의 자동 전방향 파이프라인이 완성됐다는 뜻은 아니다.

## 이번 단일 검증의 판정

새 방향 한 기준 포즈를 추출한 뒤 같은 생성기를 수치 변경 없이 실행한다. 입력 생성·컴파일·좁은 실제 연속 구간에서 실패하면 최초 단계와 입력을 보존하고 전체 루프를 시작하지 않는다. 국소 통과 후 해당 방향 전체 Walk와 기존 두 뷰 저장 입력 회귀로 확장한다. 틈, 앞머리, 외곽선, 얼굴·눈 가림과 색을 확인하며 미세 명암·성능은 별도로 남긴다.
