# 574 작은 헤어 틈의 영역 채움 — 국소 개선, 전체 채택 보류

사용자가 승인한 방향은 한 칸 수준 내부 틈을 머리 덩어리로 합치고, 외부 실루엣·큰 가르마·얼굴과 눈의 가림을 보호하는 것입니다. 실제 Walk 인접 8쌍과 전체 81쌍을 실행했습니다. 작은 내부 틈과 알려진 72번 앞머리 끝의 소실은 개선됐지만, 외부 목덜미에 새 한 셀 홈이 생겨 전체 품질 통과로 판정하지 않았습니다. 기본 OFF입니다.

## 실제 코드와 수학

- `HairRegions574.Build`가 기존 `HeadCurve511`의 실제 변형된 닫힌 선분곡선 3개와 원 경계 ID를 받습니다. Bezier 곡선이나 새 3D 메시 생성은 아닙니다.
- 양의 원 경계와 원형에서 검출한 닫힌 음의 영역을 통해 외부 영역을 구성하고, 기존 `CurveArea511.Compute`와 `SelectRegions543`으로 외부 격자 윤곽을 먼저 선택합니다. 선택된 외부 윤곽의 내부를 정의한 뒤 내부 빈 영역의 KEEP/FILL을 처리합니다. 최종 RGB 후처리, dilation/closing, 이전 프레임 복사는 없습니다.
- 내부 원 영역의 폭은 투영 논리픽셀 좌표에서 최소 caliper 폭으로 측정합니다. 측정용 convex hull을 렌더 경계로 사용하지 않습니다. 폭 2 미만은 FILL, 2 이상은 KEEP입니다. 이는 승인된 작은 틈 생략 방향을 구현한 디자인 상수이며, 논문에서 유일하게 유도된 최적값이 아닙니다. source 좌표 고정 상수와도 다릅니다.
- 기존 sweep의 닫힌 음의 성분 및 ring/edge ID를 재사용합니다. 원래 열린 큰 가르마를 선택이 우연히 막은 경우에는 실패시킵니다. 폭 2에 도달하기 전의 같은 원본 cap 부분만 작은 끝으로 인정합니다. 최초 저장 51번에서 잘못된 전영역 폭 검사가 cap까지 거부한 사실과, 그 수정 수치는 별도 기록에 보존했습니다.
- 외부 0, 머리 1, 유지할 틈 2 이상의 단일 셀 소유권을 출력합니다. KEEP 영역은 연결·입구/닫힘·다른 소유권 충돌을 검사합니다. `HeadCurve511.Areas511`과 `HeadRegion502.Prepare`의 기존 선택 출력을 대체하며, 기존 563/566 그룹 선택 위에 겹치지 않습니다. UV·표면 패킷·깊이·512/513/550 가림과 최종 Gate는 재사용합니다.
- 모델·프레임·화면 좌표 특례, 원 텍스처·눈 크기·피부색·메시 수정은 없습니다.

## 실행과 통과 범위

비교는 현재 실행의 **기준566 대 후보574**입니다. 양쪽 Clothes547 ON, Body0 영역 처리 OFF, 같은 카메라/yaw80, 480×272 논리 격자, `Rig|Walk_Loop` 1.333333초, 조명시각 3.14762 고정입니다. 제품 OFF 대 ON 비교로 바꾸어 부르지 않습니다.

- 저장 7포즈와 합성 반례: 폭 1.2/1.99 내부 틈 FILL, 2.01/4.0 내부 틈 KEEP, 큰 열린 가르마 및 정상 .75×3 양의 끝 보존을 확인했습니다. 실제 모든 방향 검증은 아닙니다.
- 실제 인접 8쌍: 16/51/62/71/72/73/76/77. 이후 코드 변경 없이 실제 연속 Walk 전체 **81쌍**을 한 번 실행했습니다. 실행 오류·공급 unsupported 0, pose/원곡선 쌍별 exact, 단일 소유권 exact, 공통 외부/부모 경계 밖 쓰기 0입니다.
- 이번 81포즈의 내부 원 가족 181관측은 폭 .799438–1.851706으로 모두 FILL입니다. 이를 181개 오류로 세지 않습니다. 큰 KEEP 가족은 합성 반례에서만 검증했습니다.
- 기존 40포즈에서 관측된 닫힌 격자 구멍은 후보에서 0입니다. 알려진 16/51의 틈, 62/77의 고립 내부 빈칸 및 72번 `(232,45)`의 앞머리 끝 소실을 피했습니다. 71–73의 끝은 모두 유지됩니다. 고립 셀 0만으로 전체 픽셀아트 품질 통과를 주장하지 않습니다.
- 눈 원본 입력 bit 차이 0, 가시 눈 버퍼 차이 0, 동일 비헤어 meta 표면의 RGB 차이 0, 전신 이미지에서 머리 ROI 밖 변화 0입니다. 이번 얼굴 회색 미재현은 과거 회색 문제 해결 증거가 아닙니다.
- 얼굴 coverage가 바뀐 48표본은 모두 해당 포즈의 머리 패킷 source ray에 원본 얼굴 삼각형·UV·알파·깊이를 계산해 대조했습니다. 누락 0, 불투명 얼굴이 앞인데 채택된 hair 패킷 0입니다. 전체 기록은 22,417 패킷 ray, 그중 FaceSkin 교차 8,885입니다. 같은 role만으로 같은 표면이라고 간주하지 않았습니다.
- 76번 대표: hair source camera Z 13.712751, FaceSkin 13.718524로 머리가 앞입니다. 최종 main depth와 원 source camera Z를 변환 없이 비교하지 않습니다. 이번 루프의 실제 몸 앞가림 표본은 0이므로 모든 앞가림 조건을 통과했다고 확대하지 않습니다.

## 전체 검사에서 확인한 한계 / 최초 단계

외부 머리 셀이 15표본 줄었습니다. 8–10번 후두부 `(208,52)` 3표본은 최종 hair→배경, 21–24번 목덜미 `(220,58)` 4표본과 41–48번 `(221,58)` 8표본은 최종 hair→몸/피부입니다. 목덜미에 실제 한 셀 홈이 보이며 외부 실루엣 보존의 전체 통과를 막습니다. `EXTERIOR_LIMIT574.png`에서 발생 전/중/후를 표시했습니다.

최초 차이는 색/가림/Gate가 아니라 `HairRegions574.Build`의 외부 `SelectRegions543(..., groups:null)`입니다. 내부 음의 가족과 양의 앞머리 끝을 부당하게 묶지 않도록 기존 그룹을 제거했지만, 외부 열린 cap의 선택에도 영향이 미쳤습니다. 예를 들어 22번의 원래 셀 면적 .282528311은 기준/후보에서 동일하고, 3×3 면적과 주변 선택도 같습니다. `BoundaryCost=.14`, 직교 가중치 `.14*.58578644`, 대각 `.14*.29289322`인 기존 식에서 그 셀 유지−생략 비용은 `(1−2A)−2*.14*.58578644 = +.270923175`로 생략을 선호합니다. 44번 A=.376187623의 같은 계산도 +.083604552입니다. 원본 면적의 손실이나 뒤 패스의 부활 문제가 아닙니다. 내부 FILL 권한과 외부 cap의 허용 형상은 여전히 분리해 정의해야 합니다. 이 결과에 새 임계값/예외를 바로 추가하지 않았습니다.

고정 격자의 세 프레임 ABA 관측은 기준90/후보78이며 실제 운동·원곡선 변화도 포함하므로 오류 수나 성공 기준으로 쓰지 않았습니다. 외부 계단 및 내부 명암의 전체 시간 안정성은 해결하지 않았습니다. 0/80 endpoint의 role은 동일하지만 head ROI RGBA는 기준160/후보168셀 차이이고 source phase도 2.503395e−6/6.198883e−6으로 완전히 같지 않습니다. 루프 색 경계까지 해결했다고 주장하지 않습니다.

## 비용 / 운영 상태

81쌍 캡처 중 `HeadRegion502` 내부 CPU/Unity 업로드 호출창의 중앙값(P95)입니다. readback·PNG 저장·별도 Face ray 감사는 이 Build 계측 뒤이며, 이것은 Player FPS나 GPU 측정이 아닙니다. 고정 OFF→ON 순서의 캡처 계측으로 최적화 효과를 주장하지 않습니다.

| 단계 | 기준566 ms | 후보574 ms |
|---|---:|---:|
| 영역 계산 | 3.194 (5.502) | 8.830 (14.365) |
| 기존 표면 패킷 생성 | 224.754 (282.191) | 226.339 (268.106) |
| Build 전체 | 260.121 (321.936) | 263.151 (313.963) |

기존 약212–228ms 패킷 병목은 남아 있고 실시간 제품 채택 조건을 만족하지 않습니다. 이번 변경의 신뢰 가능한 할당량은 미측정이며 0으로 보고하지 않습니다. 품질 회귀가 남아 있어 성능 최적화나 다른 파트 확장을 시작하지 않았습니다. 511의 다른 방향에서 가시 폐곡선 입력이 무너지는 기존 한계도 그대로입니다.

검증기와 직접 MCP 확인 모두 입력/Animator/시계 복원, Play=false, paused=false, scene dirty=false, Clothes/Body/Head/family/negative/branch/Profiler=false를 확인했습니다. QualitySettings·TimeManager 사용자 해시는 그대로입니다. 손561·기존547/550/553·사용자 에셋은 수정하지 않았습니다.
