# 534 — 50번 파임의 정보 손실과 루프 양끝 입력 분리

532 옷 후보는 계속 기본 OFF·미채택입니다. 이번에는 저장된 533 입력만 사용했고, 새 렌더·Play·제품 코드 수정은 없습니다. 기존 컴파일된 함수로 Edit 상태에서 수학 대조 1회(49/50/51 + 합성 형상 2개)를 실행했습니다. 이는 새 애니메이션 검증이 아닙니다.

## 50번: 최초 정보 손실과 최초 파임

같은 pre-fit Source 폐영역에 원본 곡선/이전 distance 근사/현재 area 근사를 각각 적용하고, 같은 CurveArea511 및 SelectRegions를 실행했습니다. 세 포즈 모두 area 경로의 곡선 float 배열·셀 면적·선택 마스크가 저장된 실제 runtime 결과와 정확히 일치합니다. Source는 이미 불투명도 사슬·투영 합집합에서 생성된 폐곡선이며, 원시 메시 전체나 래스터 중심 마스크와 같다는 뜻은 아닙니다.

50번에서 area 근사는 (201.32929993,99.57761383)→(201.66487122,97.15858459)의 chord를 받아들이며, 이전 distance 근사가 보존한 Source 배열 인덱스120의 (201.23416138,98.46575928)을 생략합니다. 이 번호는 해당 스냅샷 배열 인덱스이며 지속 메시 vertex ID가 아닙니다.

- arc 길이 2.49222293셀 / chord 길이 2.44219380셀
- 최대 수직 오차 0.24701128셀. 이전 distance 허용치는 0.09375셀입니다.
- 구현된 `∫|h(s)|ds` 오차 0.301624718셀² ≤ 현재 고정 예산 1셀². 독립 polygon-lobe 계산 0.301624700셀²와 차이 1.84e-8입니다. 하나의 lobe여서 양·음 상쇄가 없고, 임계값 인접 동률도 아닙니다.

| 포즈 | Source/distance의 (201,97) 면적·선택 | area 근사의 면적·선택 |
|---|---|---|
| 49 | 0.621625900 · 채움 | 0.543487191 · 채움 |
| 50 | 0.458947003 · 채움 | 0.388291776 · 비움 |
| 51 | 0.283452302 · 비움 | 0.221472472 · 비움 |

50번 area 결과를 다시 채울 때 현재 선택 에너지 변화는 unary +0.223416448, boundary −0.164020211, 합 +0.059396237입니다. Source/distance 결과를 비울 때는 합 +0.081914216입니다. 따라서 같은 선택기가 각각 다른 상태를 유지하는 계산과 실제 출력이 일치합니다.

최초 인과적 정보 손실은 `ClosedRegion524.FitArea532`의 chord 승인(131~150행, 특히147행)입니다. 연속 Source에도 작은 굴곡은 있지만, 새 이산 파임은 그 근사 면적으로 `ClothRegion524.Prepare`의 `HeadRegion502.SelectRegions`를 실행할 때 처음 생깁니다(ClothRegion524.cs 37~40행). 뒤의 채움·외곽선·최종 합성에서 마스크 밖으로 뚫은 사례가 아닙니다. 한 논리셀 파임 아래의 1×2 논리셀 돌출은 native2 확대에서 2×4 화면 픽셀입니다.

좌표 변환이나 면적 적분의 구현 오류는 발견하지 못했습니다. 현재 목적이 작은 총 면적 오차만으로 큰 국소 위치 오차를 허용한 것이 문제입니다. 빠진 정보는 오차의 공간 분포·국소 변위와 참조/출력 경계의 폭·span·특징 대응입니다. 이 정보 없이 새 예외·벌점·시간 필터를 추가하지 않았습니다. 이전 distance 방식으로 되돌리면 앞서 확인한 정상 얇은 끝 손상이 있으므로 그것도 수정 완료로 취급하지 않습니다.

별도 합성 대조에서 chord 길이4, 오차 면적0.75, 폐영역 면적8.75가 같은 두 형상(높이0.375 삼각형과 높이0.25 plateau)은 서로 다른 모양이지만 area 근사 후 같은 사각형이 됩니다. 이는 면적 요약이 분포를 구별하지 못한다는 반례입니다. 실제 50번이 동일 면적 동률이었다는 증거는 아니며, 이 작은 합성 특징을 생략하는 것 자체를 미술 오류라고 판정하지도 않았습니다. 2016 논문의 참조 extrema/폭 대응 항은 현재 미구현입니다.

## 루프 양끝 28색 표본

28개 모두 같은 실행의 527 옷 ON 대조와 532 area 후보가 양끝 각각에서 RGBA까지 같습니다. 이 28표본에 대한 area 변경의 추가 효과는 0입니다. 같은 실행 대조의 근접 표면 매칭 표본은30개, 후보는28개지만 서로 다른 매칭 집합이므로 30→28을 품질 개선으로 세지 않습니다.

과거 527 FullLoopB의 원본 OFF도 같은 근접 매칭 기준으로28표본이며 그중 좌표27개가 겹칩니다. 다른 실행·광원이므로 현재 실행의 동등 입력 대조로 쓰지 않습니다.

- 위상0=0.0000025033950806 / 위상80=0.0000061988830566. 정확히 같은 포즈가 아닙니다. Source 투영 제어점의 최대 좌표 차이 0.000854492셀, area 곡선 차이 0.000259399셀입니다.
- clip/회전/offset/ortho와 기록된 skyHour 5.0164880753, captureDelta는 같습니다. 전체 bone/skin 결과·카메라 행렬·모든 광원/그림자/world 입력·shader clock·history texture는 저장되지 않았습니다.
- UV 허용차2e-5의 근접 매칭은 동일 입력이 아닙니다. 정확히 같은 meta+UV인 RGB 변화 표본은0이지만, 이것만으로 전체 색 경로가 정상이라고 인증하지 않습니다.
- 측정한 FINAL.bin은 world Composite 전의 Full319View335.colour입니다. 이후 world motion history가 이 저장 버퍼를 거꾸로 바꿀 수는 없습니다. 상류·눈 history 전체를 배제한 조사는 아닙니다.

결론은 **새 area 회귀가 이28표본을 만들었다는 근거 없음 / 같은 입력 루프 회귀 여부는 미판정**입니다. 개별 RGB 변화의 정확한 분기 원인은 아직 미확정이며, 조명이나 history 때문이라고 단정하지 않습니다.

## 기존 5표본과 적용 상태

기존 5표본의 최초 변경은 OwnerLines333의 인접 영역·외부 노출 재분류이며, prepared RGB는 같고 `postLine=Before×0.55` 오차0입니다. 42번 옷(209,57) 생략으로 빈 공간(209,55~56)이 외부와 연결되어 hair4셀이 외곽선으로 바뀌고, 44번 옷(227,65) 생략은(226,65)을 노출합니다. 이는 원색 변조 버그가 아닙니다. 원인과 시각적 채택 여부는 별개이며, 전체30표본도 모두 오류수로 세지 않습니다. 자세한 GPU 근거는 이전533 기록을 재사용합니다.

활성348/44d13c0와 기본 OFF 실험511/513/532를 구분합니다. 옷 슬롯3만 시험 대상이며 손·피부·머리로 확장하지 않았습니다. 얼굴 회색530/533 미재현은 해결 증거가 아닙니다. 내부색·212ms 패킷·시간 선택 미채택은 별도 미해결입니다. 이번 Edit 수학 호출은 OFF guard를 통과하며 scene/input/Animator/clock/hook을 바꾸지 않습니다. 마지막 직접 복원 증거는533의 clean Edit/OFF 기록입니다. 사용자 Quality/Time 설정과 제품 소스 해시는 보존합니다.
