# 눈 특징 공동 배치 — 현재 결정

요청 결과는 같은 pose에서 subpixel 위상만 달라질 때 눈 클러스터의 내부 형태·연결·색 family·좌우 상대 위치가 재결정되지 않는 셀 배치 출력이다. 제품·Unity·31·34·원본은 변경하지 않는다.

## 입력과 범위

- 기존 `TemplateRole.asset` / `TemplateRGBA.asset`의 실제 20셀과 색을 사용한다. 현재 찌그러진 최종 raster는 기준 형태로 채택하지 않는다.
- 이 자산은 기존 Template216 참고 자산이다. 모든 각도·blink의 사용자 승인 디자인이라고 새로 주장하지 않는다. 상안검 role6도 이 자산에 없다.
- 저장 5pose마다 원본 S2 홍채 표본의 투영 중심을 구하고, 좌우 평균을 공통 기준점으로 삼는다. 각 pose의 기준점 주변만 이동한다. 템플릿의 좌우 위치/형태/색은 바꾸지 않는다. 다른 pose에 동일 템플릿을 놓은 열은 **이동 진단용 차용**이며 pose에 맞는 형상 검증이 아니다.
- 모델/색·역할 자산/스타일 fingerprint와 pose-state token이 캐시 키다. 등록되지 않은 blink·pose는 기존 열린 눈으로 대체하지 않는다.

## 실제 연산과 좌표

좌표는 논리 셀 단위의 2D 이미지 좌표이며 x 오른쪽, y 아래쪽이다. 정수 셀 좌상단 q의 중심은 q+(.5,.5)다. 480×272 원본/저장 좌표계를 공통 부모로 사용한다. 단위 배율은 1, 회전/확대는 없다.

`Template216 셀 q_i → 상대 정수 오프셋 q_i−q_ref → 공통 이동 t → floor(t+.5) 한 번 → q'_i=q_i+floor(t+.5) → 해당 셀의 원래 RGBA8 직접 출력`

q_ref는 두 템플릿 홍채 중심의 평균이다. 실제 pose의 a는 두 원본 S2 투영 중심의 평균이고, t=a−q_ref+phase다. x/y 위상은 각각 0..1을 1/64 간격으로 시험한다. 같은 t를 20셀 모두 공유한다. 개별 셀 반올림·개별 눈 반올림·최소 셀 수 보충·대칭화는 없다. 공통 snap의 위치 오차는 각 축 ±.5셀 이내다. 위치 자체는 정수 단위로 이동하며 연속 영상 움직임을 완성했다고 주장하지 않는다.

비교군은 현재 `IrisAllocated19/BeforeIris19`의 면적 반올림·경쟁 비용·UV 순위 코어다. 저장 S1/S2/S3에서 현재 Classify/알려진 깊이 관계를 적용한 intrinsic packet을 사용한다. 각 1/4셀 표본 footprint를 연속 이동하여 논리 셀과 겹치는 면적을 보존적으로 누적한다. 이는 촘촘한 위상 probe용 재구성이며, 새 16표본 GPU 렌더/완전한 가림 selector를 재현한 것이 아니다. 면적 합은 이동 전후 같아야 하며, 후보를 유리하게 하려고 일부 표본을 버리지 않는다.

## 합격·실패

- 후보 5×65×65 배치에서 reference-cell ID, 상대 좌표, role/eye family, 색, 연결, 좌우 관계가 정수 평행이동을 제외하고 정확히 동일해야 한다.
- 최종 RGBA8은 대응 template 셀과 정확히 같아야 한다. 외부 family/새 색/보간은 허용하지 않는다.
- state/source/style 변경을 조용히 재사용하면 실패다. 실제 visibility는 별도 입력이며 일부/전체 가림 시 보이는 셀이 줄어드는 것은 위상 실패로 세지 않는다.
- 기존 allocator의 shape 변화가 없으면 억지 반례를 만들지 않는다. 수치와 실제 contact PNG를 함께 보고한다.
- 실제 pose별 디자인 적합성, 상하 안검/깜박임, hair 가림, 실제 연속 프레임은 별도 미검증이다. 네 셀 보존만으로 전체 눈 해결이나 미감 합격을 선언하지 않는다.
