# B35 — 상점 가구의 공통 투영과 용도별 구성

## 현재 결정

사용자는 B34의 대부분 가구 각도와 사물 부족을 거절했다. B34의 지붕/이미지 프레임 깊이 수정은 유지하되, 그 기술 검사로 원본 그림의 각도가 맞는다고 판정하지 않는다. 같은 `PlannedPixelShop33` 한 채를 변경한다. Player, Camera, 통로와 기존 출력은 보존한다.

후보는 (1) 검증된 native 2:1 외부 팩, (2) 같은 투영 가이드에 따른 신규 생성, (3) 기존 그림의 명시한 평면을 정규 면으로 재투영하는 것이다. 현재 보유한 B31 팩은 각도는 일관되나 이미 디테일 부족으로 거절된 입력이다. 새 생성의 프롬프트는 각도를 보장하지 않는다. 따라서 **직선 선반 한 개의 평면 재투영을 최소 실험**하고, 실제 이미지가 유효할 때만 해당 평면 종류로 확장한다. 비평면 돌출물을 단일 homography로 복원했다는 주장은 금지한다.

근거: [OpenCV homography tutorial](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)의 평면 대응점 변환이다. 선반 정면 안의 상품은 그 면에 그려진 2D 아트이며, 상품별 실제 깊이를 복원한 것이 아니다. 계산대 위 계산기, 화분 등은 별도 명시 면/스프라이트로 취급해야 한다.

## 좌표·입출력 계약

- 입력은 B34 원본 PerfectPixel 자동 검출 결과와 원본상 면의 네 꼭짓점이다. source 좌표는 좌상단 원점, x오른쪽/y아래, 픽셀 중심 단위다. 이 단계는 픽셀 정규화를 다시 하는 것이 아니라 **기하 재투영**이다.
- canonical representation은 역할 도면의 미터 단위 3D 평면 네 꼭짓점, source UV 네 점, 가림 깊이다. 공통 건물 좌표 X/Y/Z와 카메라 local pitch30/yaw45를 그대로 쓴다.
- `r=(1,0,-1)/sqrt(2)`, `u=(sin30/sqrt2,cos30,sin30/sqrt2)`, `d=(cos30/sqrt2,-sin30,cos30/sqrt2)`.
- raster는 `x=PPU*dot(r,P)`, `y=-PPU*dot(u,P)`로 만든다. 기존 PPU127을 유지하며, 오브젝트별 캔버스는 실제 투영 범위로 계산한다. 모든 오브젝트를 같은 W×H로 만들지 않는다.
- 각 출력 셀 중심에서 평면 역변환→source 최근접 단일 샘플을 수행한다. RGB를 새로 그리거나 팔레트를 바꾸지 않는다. 깊이는 같은 canonical 평면의 P를 저장한다. 닿는 면은 같은 꼭짓점을 공유한다.
- 손실: 기존에 다른 기울기로 그려진 계단 패턴을 새 격자로 사상하면서 셀 재배치와 일부 중복/누락이 발생할 수 있다. 이것을 PerfectPixel의 무손실 정규화라고 부르지 않는다. 낮은 목표 해상도로 축소하는 해결책은 쓰지 않는다.
- 자동 invariant: 수평 세계축의 raster 기울기는 ±0.5, 수직축은 dx=0, 공유 꼭짓점 동일, 면 면적 양수, native 색 표본은 source에 존재, 유효 alpha에 대응하는 유한 깊이, 선언한 체적/지붕 범위 내. 그림체/정보 보존/설득력은 이 조건만으로 합격하지 않는다.

## 작업 그래프

`실제 참고 화면의 사물 목록 → 역할/부착/접근 영역 도면 → 선반 평면 최소 실험 → 원본별 면/돌출물 계약 → 개별 아트와 배치 → 기존 prefab 통합 → 실제 화면/통로/가림 최종 관찰`

실험에서 상품이나 가구가 심하게 왜곡되거나 면 분리가 불가능하면 해당 입력은 통합하지 않고 공통 기하 가이드로 새 입력을 제작한다. 임의 offset/rotation으로 실패를 숨기지 않는다. 결과와 남은 제한은 이 파일에 추가한다. 새 가구는 통로가 아니라 벽/가구 위/재고 구역의 의미 있는 부착점에 배치한다. 참고작 실제 관찰과 제안은 `docs/artifacts/building35/reference-object-plan.md`에서 구분한다.

## 실제 결과·현재 재개점

2026-09-27 같은 기지 건물에 적용했다. 기존 세 선반을 면별 재투영했고, 가려진 상판을 복원할 수 없는 계산대/진열섬은 새 빈 계산대 원본과 명시한 치수 템플릿으로 대체했다. 신규 냉장장·세척대·청소 수납장·상자·통·화분·등록기·사과 트레이는 각각 생성1회, 원본 PerfectPixel 자동 검출1회다. 생성 프롬프트/출처/원본과 자동 격자 receipt를 보존한다.

**정규화 이후 기하 재표본화는 실제로 있다.** `project_faces.py`는 source 네 점→canonical 평면의 역 homography로 단일 표본을 선택한다. 선반틀3면은 목표 축에 놓이나, 그려진 내용물/내부선까지 완벽한3D가 되는 것은 아니다. rear holdout 잔차2.56/3.56px를 보존한다. 화분·통·등록기·트레이4종은 명시된 세로2D층이고 내부 기하의 정확한 복원이 아니다. 모든 물체를 같은 W×H로 만들지 않으며 공통 표시127px/m를 유지한다.

중심선 polygon만 쓰는 첫 실험에서 테두리·발의 source 일부가 잘리는 것을 발견했다. 이후 source 실루엣을 가장 가까운 명시 평면으로 외삽하고 같은 면XYZ를 운반했다. 구조 꼭짓점과 아트 돌출의 범위는 receipt에서 구분한다. 접지는 source 셀 네 모서리 전체의 최소Y로 계산하며, 소품 부착 높이는 실제 수평 지지면Y를 쓴다. 외삽 장식과 Collider는 완전히 같은 형태가 아니다.

왼쪽 벽의+X 사용면은 카메라에서 뒤쪽이므로 정면 그림과 모순됐다. 그 선반을 오른쪽 벽(-X 사용면), 냉장장은 뒤벽 왼쪽, 진열섬은 x1.8/z-2.1로 옮겼다. 외곽·출입구·재고실과 기존 셸/카메라는 유지했다. 역할계획20개는 큰 가구8 + 상판소품3 + 화분2 + 물류통2 + 재고상자5다. 선반 속 이미 그려진 물품은 추가로 세지 않았다.

`graph.json`의 입력→개별 면/표시 자산→같은 prefab 연결→실제 관찰→최종 계산을 완료했다. 실제 Play Mode StepMove12/12, 벽 충돌, 같은 Player/Camera ID, 내부 지붕숨김/외부복원, imported alpha/depth 불일치0·프레임누출0·높이범위 지붕누출0. Console 오류11→11, 이력 유지/추가0. 물리 키 입력/빌드/저장로드/GPU 깊이동등성은 검사하지 않았다. overview는 조망용 재프레이밍이고 play-interior는 실제1114×857 화면이다. 작은 GameView의 줌 범위와 native1배의 기존 불일치는 남는다.

**사용자 확인:** 실제 Unity 두 화면에 대해 “지금은 훨씬 더 정상이야 각도랑 배치 같은 거 자연스러워졌어 그런 식으로 쭉 이어가”라고 답했다. 큰 가구의 각도와 현 배치를 유지 기준으로 기록한다. 모든 아트·세부선·모든 시점의 완벽함까지 승인받았다고 확대하지 않는다. 다음은 이20개를 보존한 벽/상판/직원용 작은 소품 보강이다.
