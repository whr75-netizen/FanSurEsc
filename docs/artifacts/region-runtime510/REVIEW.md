# 곡선 영역의 런타임 표현 검토510

**설계 제안이며 구현하지 않았습니다.** 508은 `909e324`, 509 비채택·철회는 `95a1382`에 기록했습니다. 현재 활성348, 기본 OFF인508, 사용자 설정을 보존했습니다. 이 검토에서는 새 측정·촬영·라이브러리·렌더 코드를 추가하지 않았습니다.

## 결론과 현재의 불일치

최소 경로는 **지속 ID를 가진 저작 닫힌 곡선 → 현재 포즈의 제어점 → 곡선 영역의 격자 선택 → 현재 가시 표면 패킷 → 기존502의 공통 경계 강제**입니다. 원본 메쉬는 변형·색·깊이·가림을 제공하며, 모든 잔가닥과 미세 틈을 최종 그림에 복제하는 기준으로 쓰지 않습니다. 의미 있는1픽셀 디테일을 일괄 삭제하는 규칙도 넣지 않습니다.

현재 `HeadRegion502.Prepare`는 모든 머리 삼각형을 투영해1/8격자에서 경계를 추출합니다. `ClosedCurve`가 만든 RDP 곡선은 지금 **진단용**입니다. 실제 선택 입력은 `HeadArea505.Build/Compute`의 원본 가시 면적입니다. 따라서 현재 구조에서는 설계 곡선이 영역을 소유하지 않습니다.

저장된 인접3포즈에서 source ring은20/17/13개, source point는1868/1902/1926개였습니다. 진단 곡선도 매번 재생성되며 지속적인 제어점 ID가 없습니다. 이 수치는 표현의 변화와 재구성 작업의 근거입니다. 오류 수나 불필요한 출몰 수로 해석하지 않습니다.

## 미리 만들 데이터와 실제 갱신할 데이터

| 데이터 | 저작·소스 변경 때 준비 | 실제 변화 때 갱신 |
|---|---|---|
|닫힌 머리 영역|piecewise cubic Bézier 제어망, 곡선/영역/필요한 hole ID, 부모 관계, 지원 방향|현재 포즈의 제어점·접선·투영 곡선|
|변형 anchor|원본 submesh·primitive·barycentric 또는 본 기준 anchor, 소스 topology/UV 서명|현재 변형에서 anchor와 handle 기준축 평가|
|표면 검색|실제 triangle ID·adjacency·재사용 배열·BVH topology|현재 정점으로 bounds refit, 현재 가림/후보 질의|
|곡선 영역과 격자|고정된 ring 관계와 설계 규칙|곡선-셀 교차·선택·닫힌 셀 경계. 투영/pixel phase/offset 변화도 반영|
|표면 패킷|검색 구조와 재료/UV 참조|triangle·barycentric·UV·world·depth·owner·가시성|
|색·명암|기존 팔레트/셰이더 참조|현재 조명과 패킷으로 기존 방식의 색 계산|

머리 제어점이 같아도 얼굴·팔·다른 가닥·월드가 움직이면 가림을 다시 평가합니다. 조명만 바뀌면 곡선을 다시 저작하지 않지만 RGB는 갱신합니다. 카메라·clip·포즈가 바뀌면 곡선을 현재 변형에서 평가하며 정지 결과를 재생하지 않습니다. 메쉬 topology/UV/rig가 바뀌면 묵은 anchor를 재사용하지 않고 명시적으로 무효화합니다.

BVH는 새 외부 라이브러리 제안이 아닙니다. 현재 triangle/bounds/Bary 자료를 사용하는 정적 topology 색인이 필요하다는 뜻이며, 그 구조가 이미 존재한다고 주장하지 않습니다. 기존 BakeMesh provider를 유지하고 같은 현재 변형을 공유합니다. 별도의 skin/본 평가 체계를 동시에 만들지 않습니다.

## 한 가지 최소 구현 경로

1. **전체 머리의 저작 영역 자산을 준비합니다.** 현재 선호 외형·게임 각도의 경계는 초안으로만 참고합니다. 큰 머리 덩어리, 의미 있는 끝과 필요한 틈을 닫힌 제어망으로 정리하고 지속 ID와 소스 anchor를 저장합니다. 잔가닥/미세 틈을 모두 보존하는 조건은 없습니다. 현재 이 자산은 없으며, 이것이 첫 필수 작업입니다. ROI 박스·볼록껍질·매 프레임 RDP로 대체하지 않습니다.
2. **`Prepare`에서 원래 추출을 실제로 우회합니다.** Designed 분기는 `Union(projected,indices)`나 `HeadArea505.Build`를 먼저 실행하면 안 됩니다. 현재 제어점과 투영에서 곡선 영역/bounds를 직접 얻습니다. 504/505/508은 대조 분기로 남으며 새 경로 앞뒤에 직렬로 붙지 않습니다.
3. **저작 곡선의 영역을 선택 입력으로 사용합니다.** 곡선-셀 교차 오차를 제어하고 내부/외부를 winding으로 판단합니다. 기존 `CellAreas`의 signed ring·rect clip·area 구조는 출발점으로 재사용할 수 있습니다. Bézier 평가·오차 상하한·ring 유효성 검사는 새로 필요합니다. 단순 저해상도 alpha나 coverage 임계값 채움이 아닙니다. 최초 비교는 기존 `SelectRegions` 비용/동률 규칙을 유지해 입력 효과만 분리합니다.
4. **현재 표면에서 패킷을 질의합니다.** 정적 색인의 bounds를 현재 포즈로 갱신하고 후보만 검색합니다. `Packet/Bary/AddQuad/Piece`와 원본 색/UV를 재사용합니다. 498에서 확인한 같은 camera ray의 깊이 비교와 가시 후보 순위를 이어받습니다. 같은 role를 같은 surface로 보지 않습니다. 현재1.1셀 donor 지원 범위를 임의 확대하지 않습니다. 모두 가려짐과 지원 donor 부재를 구별하고, 원본 coverage로 몰래 복귀해 통과시키지 않습니다.
5. **기존 공통 경계 권위를 소비합니다.** 선택된 닫힌 셀 영역이 하나의 Hair/Parent mask를 만들고 `Draw`, `Region502Clip`, Prepare·눈 이후·최종 `Gate`에 전달됩니다. 원본 hair mesh alpha는 이 분기에서 최종 허용 영역이 아닙니다. 얼굴·눈·몸·팔레트와 기존 외곽선 규칙은 유지합니다.

연속 저작 곡선 C와 양자화된 닫힌 셀 경계 C_Q를 구별합니다. 픽셀 전체를 채우거나 생략한 뒤에는 **C_Q가 최종 허용 경계**입니다. 원본 메쉬의 색/alpha가 그 밖에서 살아남으면 위반입니다. 연속 C로 픽셀 내부를 다시 매끈하게 잘라 최종 그림을 만드는 방식은 제안하지 않습니다.

필요한 변경 책임은 기존 `HeadRegion502.Prepare`의 형태 입력/패킷 검색과 저작 영역 자산입니다. 기존 렌더 패스·Shader/Gate 권위는 우선 재사용합니다. 이전491의118삼각형 단일 ribbon과 열린 경로 선택을 전체 머리 해법으로 재포장하지 않습니다.

## 정확도·디자인·실제 애니메이션 계약

- 기술 검증은 같은 provider 포즈·카메라 행렬·480×272 공통격자와 Native2×phase, 닫힘/부모/hole/self-intersection, 교차 오차 상하한과 선택 모호성, 실제 triangle/UV/depth/owner 및 가시성, 모든 최종 패스의 C_Q 밖 침범0을 확인해야 합니다. 새 mask를 원본1배 alpha로 다시 clip하지 않습니다.
- **505 면적/마스크와 모든 셀이 같아야 한다는 조건은 넣지 않습니다.** 505/508은 원본의 물리·가림·면적 대조용입니다. 생략/통합한 형태를 명시하고 전신 기본 크기에서 머리 덩어리·끝·필요한 틈·외곽 계단 리듬·폭 급변·불필요한 순간 출몰을 검수합니다. 고립0·연결성만으로 아트 통과라고 하지 않습니다.
- 최소 실제 구간은 기존 .2625/.2750/.2875 및 .8625/.8750/.8875입니다. 같은 곡선 ID/호길이 위치의 운동·곡률·가림과 픽셀 선택을 대조합니다. 발생 경로 설명과 정지 프레임 변화0은 품질 통과가 아닙니다. 정상 운동/가림은 유지하며, 국소 판별 후에만 필요한 한 루프 범위를 정합니다.
- 제어점 갱신·곡선/셀·검색 색인 refit/가림·패킷/quad/upload·기존 renderer 전체를 구분해 측정해야 합니다. 실제 변형과 가림이 바뀌는 Walk에서 비계측 기준/후보를 비교합니다. 기존 BakeMesh/렌더 기본 비용을 최종 frame 평가에서 제외하지 않습니다.

**남은 이웃비용 사건은 별도입니다.** (224,58)의 .8625/.8750/.8875에서 면적은 감소했지만 이웃 기여가 +.0820101→−.1640202로 바뀌었습니다. 현재 선택기는 면적 불일치와 .14의8이웃 경계 길이를 최소화하며 명시적인 계단 리듬·시간 대응 목표가 없습니다. 지속 제어점과 곡선 입력이 이 사건을 자동 해결한다는 근거는 없습니다. 같은 설계 품질의 다른 공동 배치와 에너지를 비교해 남으면 선택 목표 문제로 유지합니다. 이번 입력 교체에 비용함수 변경이나 history/RGB 필터를 동시에 더하지 않습니다.

내부 명암의 색 덩어리와 전신 다른 파츠는 이번 최소 범위에서 재설계하지 않습니다. 머리 coverage 경로가 통과해도 전체 픽셀 튐 해결이라고 보고할 수 없습니다. 기본 OFF는 실제 성능·디자인·애니메이션 검증 전까지 유지합니다.

## 기존 연구와의 관계

[Pedro Medeiros의 Cluster Sketching](https://saint11.art/pixel_art_articles/article2/)은 큰 색 덩어리에서 시작하고 불필요한 고립 픽셀을 제거하거나 의미 있는 작은 덩어리로 재설계하며 계단 배열을 다룹니다. [Basic Shading](https://saint11.art/pixel_art_articles/article4/)은 축소 사진 복제보다 읽힘을 위해 세부를 생략하는 설계 판단을 설명합니다. 이를 저작 영역과 검수 기준으로 연결합니다. 지금 눈/입 크기·팔레트를 바꾸거나 특정 자동 알고리즘이 입증됐다는 근거로 쓰지 않습니다.

[Kolmogorov·Zabih](https://www.cs.cornell.edu/~rdz/Papers/KZ-PAMI04.pdf)는 graph cut으로 최소화할 수 있는 binary energy의 범위를 다룹니다. 현재 solver 형식의 기술적 타당성과 프로젝트의 pixel-art 목표가 적절한지는 별개입니다. 에너지 최소값이 아트나 시간 품질을 자동 증명하지 않습니다.

이 문서는 코드·저작 자산을 만들지 않았고 새 성능/아트 통과를 주장하지 않습니다. 런타임 소스와 운영 상태는509 종료 증거를 유지했습니다. 문서 변경에 전체 Unity 검사나 촬영을 반복하지 않았고 Library403도 재시도하지 않았습니다.
