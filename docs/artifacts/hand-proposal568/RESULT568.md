## 사용자 제안의 최소 연결

|책임|제안과 현재 한계|
|---|---|
|손가락별 영역|원 index/UV/skin과 혼합 접합을 유지하고 논리 계통을 첨부하는 것이 먼저다. 물리 메시 분할이 필수인 근거는 없다. 뼈 가중치만으로 유일한 닫힌 디자인 경계가 정해지는 것은 아니다.|
|가시 영역 선택|finger ID·원표면 patch ID·양자화 선택 region ID를 분리한다. 같은 원표면 접합의 coverage는 보존하고, 다른 깊이의 손/다리를 재질 단위로 합치지 않아야 한다. 손가락마다 독립 Fit/cut한 OR만으로는47을 막지 못한다.|
|겹침 순서|실제 겹침 ray마다 불투명 표면의 깊이와 유지 상태를 비교해야 한다. 손가락 전체의 중심 깊이로 정한 우선순위 하나는 국소 겹침/굴곡을 보장하지 않는다. 같은 손가락도 앞/뒤 표면이 다르다.|
|뒤 표면 공급|앞 관리표면을 생략하면 같은 ray의 다음 유지된 원표면 triangle/bary/UV/depth/normal/명암 패킷을 공급한다. 다른 native4 위상은 같은 ray가 아니다. 비관리 얼굴/눈/world의 정상 앞가림은 건너뛰지 않는다.|
|외부선색|최종 가시 coverage의 외부 실루엣 안쪽에서만 적용한다. 선색이 alpha/영역을 재확장하면 안 된다.|
|내부 겹침 선색|실제 국소 가림 경계와 논리 출처를 함께 사용한다. 단순 뼈 ID 변경으로 손목/마디에 선을 만들지 않는다.|

현재 `Part540.areas/selected`와 Body0 마스크는 재질당 한 상태이며, raw/native/prepared 패킷은 각 샘플의 첫 승자만 보관한다. 기존 `ClothSurface525.Geometry/Visible`의 원기하와 sparse quad 공급은 재사용할 수 있으나 원표면별 유지 상태/후보 소비 계약이 부족하다. 메시만 나누어도 이 누락은 해결되지 않는다.

`OwnerLines333.compute`는 이미 외부 `outer&&!thin&&eligible`(reason1), 내부 `internal&&!thin`(reason2)를 구분하고 `_LineTone`/기존 팔레트를 적용한다. 현재 입력은 part·coverage·깊이 이웃이며 finger ID가 없어 손가락별 겹침 선색이 구현됐다고 할 수 없다. 기존 reason 경로 재사용이 후보이며 새 피부색 상수를 정하지 않았다. source ray 패킷을 양자화 이동했다면 그 ray의 가림 증거를 함께 전달하거나 destination ray에서 전체 후보를 다시 계산해야 한다. 다른 ray의 깊이를 혼용하면 안 된다.
