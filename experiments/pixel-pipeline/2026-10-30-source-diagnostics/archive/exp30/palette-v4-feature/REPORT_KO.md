## 9쌍에서 무엇이 확인됐나

원본 모델의 실제 material/UV unlit 값, 각 UV의 원본96×96 texel 패치18장, 원래 투영된 native512×640 원색과 논리 셀 주변을 모두 대조했습니다. sourceFeatureId는 여전히 null입니다. 텍스처에 획이 보인다는 관찰과 저자가 지정한 의미 특징이라는 주장은 구분합니다.

- **7쌍(0,2,3,5,6,7,8)**: 원본에 그려진 획·선/바탕의 측정 색차를 보존할 근거가 있습니다. 차이는 단순히 v2 RGB가 다르다는 데서 가져오지 않았습니다. 실제 source ΔL은 약0.0134~0.0304입니다. 서로 다른 chart의 경우에도 표면을 합치지 않고 각 원색의 차이만 보호합니다.
- **1쌍(4)**: 원본의 획과 source ΔL=0.048315는 확인됐지만 실제 Q가2/1로 다릅니다. 원색 차이와 어두운 조명 단계가 상쇄될 수 있습니다. 이 쌍은 **같은 Q의 반사실 비교에서** 특징 대비를 보호하고, 실제 서로 다른 Q의 출력 차이는 별도로 기록했습니다. 원색이 다르면 최종 화면에서도 반드시 같은 크기의 차이가 나야 한다고 강제하지 않았습니다.
- **1쌍(1)**: source ΔE=0.005759, ΔL=0.003464로 국소 투영색이 거의 같습니다. UV 패치 자체에는 획이 있으나 이 두 표본 사이에 v2의 ΔL=0.083151만큼 선명한 국소 경계를 복원할 근거는 부족합니다. 따라서 이 쌍은 강제 보호하지 않았습니다. 텍스처에 특징이 없다고 단정한 것도 아닙니다.

v2 대비 자체가 원본 대비의 정답도 아니었습니다. 예를 들어0/6/7/8쌍은 v2의 밝고 어두운 순서가 실제 원색 순서와 반대입니다. 후속 후보는 그 순서를 복원하지 않고 **실제 source 색차의 방향**을 기준으로 삼았습니다.

각 쌍의 source RGBA/UV/재질, 실제/동일Q, 원래 픽셀 크기와 정수 확대는 INDEX와 `NINE_NATIVE_AUDIT.json`/`BUDGET_NINE.json`에 있습니다. 최종64×80과8배 PNG 및9쌍 주변 source/v3/후속 PNG도 직접 열람했습니다.

## 바뀐 연산과 보호 제약

원본 native 팔레트색은 계속 실제 texel medoid에서 생성합니다. RGB 평균·스크린샷 평균·임의 갈색·최종RGB에 연속 g 곱셈은 없습니다. 16색은 사용자 확정 제약이 아니므로16/32/64색을 나란히 비교했습니다.

색수에 따라 명암 폭까지 작아지지 않도록 shadow 목표 ΔL=**0.043678819**를 공통 고정했습니다. 이는 v3 native 인접 간격의 중앙값에서 온 측정값입니다. Q0/1은 그 목표에 가까운 아래 native색, Q2/3은 원색 기준값이라는 구조와 기존 Q 라벨을 유지했습니다. 실제 사용색수는 팔레트 예산과 다를 수 있습니다.

보호 제약은 `출력색이 조금이라도 다름`이 아닙니다. 감사로 선택한8 source 쌍 각각에 대해, **모든 동일 Q에서 원본 ΔL 이상이며 원본과 같은 방향**이 되도록 native 팔레트 기준 배치를 제한했습니다. 좌표별로 RGB를 덮는 예외는 없습니다. 제약 데이터에는 원본 material/UV/RGBA가 있으며, 실행 selector에는 화면좌표나 g를 넣지 않습니다.

컴파일러는 원색 L 순서를 보존하면서 native 기준색 오차를 줄이는 제약 배치를 구합니다. 그 배치를 통과하는 단조 원색-L 선택 곡선을 만들어 같은 색계열 전체에 적용합니다. 따라서 감사 표본 외의 색에도 영향이 있습니다. 원래 색차가 거의 같은 곳을 독립된 먼 갈색 은행으로 보내지 않습니다. 현재의 단일 warm 색계열에 한정하며 다른 모델/색계열에는 해당 source의 검증한 제약과 팔레트를 생성해야 합니다.

`P[원색기준ID][기존 Q(g)]`를 먼저 만들고 직접 출력합니다. 간격 배율 m은 기존처럼 `Lab(anchor)+m*(Lab(P)-Lab(anchor))`에만 적용합니다. m은 원색 선택 곡선/UV/appearance/Q/다른 안의 입력을 바꾸지 않습니다. m=0/기준단계3은 실제 native 기준색으로 고정됩니다. **대비 보존 검사는 기본 m=1 기준**이며 사용자가 다른 m을 선택했을 때도 같은 미술 대비가 보장된다는 주장은 하지 않습니다.

이 제약은 이번 감사의8 source 쌍에 대한 수정입니다. 모든 원본 특징의 자동 발견·저자 의미 라벨 복원·다른 모델의 자동 색계열 추출까지 완료했다고 확장하지 않습니다.

## 113개 경계와 단셀 증가의 정확한 의미

113은 전체 경계 수가 아닙니다. 보존안의 **동일 appearance·동일 Q인 인접400쌍**에서 v2는29개 가시 RGB 경계, v3는140개입니다. v3에서 **113개가 새로 생기고2개가 합쳐져** 순증111개입니다. 서로 다른 geometry/chart 경계를 전부 같은 특징 경계로 합산한 통계도 아닙니다. 정규화안은394쌍에서 v3 추가109개입니다.

보호64는 같은400쌍에서236개 가시 톤 경계, v2 대비 추가207개입니다. 이 수와 단셀184개를 새 미술 특징의 수로 해석하면 잘못입니다. 후속 데이터는 **원래 appearance/측정 가시표면의 영역 ID와 팔레트 톤 ID를 별개로 유지**합니다. `SOURCE_DOMAIN_MAP.json`의 기존 추정 영역 ID는 모든 색수/보호 여부에서 같습니다(보존181, 정규화184). 이 수 역시 저자의 의미 가닥 수는 아닙니다. 팔레트 톤 경계를 자동으로 source-feature 곡선에 승격시키지 않습니다.

단셀을 실제 원색 이웃과도 비교했습니다. 색 이름만 다른 아주 가까운 단셀이 늘어, 새로 과장된 고립색 대비의 중앙값은 v3 .013799에서 보호64 .001123으로 줄었지만 최대값은 여전히 .049740입니다. 단셀 수 증가를 곧바로 무의미한 노이즈라고도, 반대로 전부 진짜 특징이라고도 판정하지 않았습니다.

같은 A/Q의 네 이웃이 있는 단셀은 보존안 v3에서4개, 보호64에서9개였습니다. 이 중 원색 L이 이웃 범위 안에 있는 부드러운 톤 분절은2→6개입니다. 해당 제한 표본에서 원색에 없던 새 L 극값은0개였으나, 표본이 작아 전체 노이즈 부재의 증거로 쓰지 않습니다. 물리적으로 같은 chart/표면까지 요구하면 해당 내부 표본이0개라 그 조건의0실패는 통과 근거가 아닙니다.

나머지 단셀은 특징/기하/조명 경계 또는 원색 극값 주변이며, native footprint의 동일 chart·appearance 표본 수와 원색 범위를 전부 기록했습니다. 얇은 진짜 획은 면적 과반이 아니어도 유효할 수 있어 면적/단셀 크기로 삭제하지 않았습니다. 실제 PNG에서도64색은 v3의 합쳐진 약한 획 대비를 되돌리면서 작은 톤 조각이 늘어나는 회귀가 있습니다. **큰 점프와 대비 손실의 수정은 했지만 색면 정돈은 미완**입니다.
