# R25 전신 1×1 시험 진입점

## 입력과 출력

기존 GameMap1/Gameplay397를 사용하는 검증 전용 소스다. 진입점은 `T3ApertureTrial154.Start(cache, run, "native-common-grid")`다. `common-grid`를 주면 상태·파일을 변경하기 전에 실패한다. 원본 평가 메시 → 같은 카메라의 960×544 물리 화면 → 캐릭터 1×1 주소 → `(384,0,192,352)` crop의 소유권 패킷 순서다. 월드 색은 기존 2×2 주소에서 읽고 월드 깊이는 원래 물리 위치에서 읽는다. 화면 크기와 기존 제품 시작 경로를 유지한다.

같은 후보·원본 주소의 위-아래 위치는 기존 아틀라스 방향을 쓴다. 원점 `O`, 근접 셀 위상 `δ`에서 캐릭터 주소는 `floor(p+0.5−O−2δ)`, 월드 색 주소는 `floor((p+0.5−O)/2−δ)`다. 정적 검사는 두 경로의 주소와 픽셀 배율을 따로 검증한다.

## 실행 계약

- `GraphOwner154`를 월드 카메라 전에 현재 표시 순번으로 등록한다. 기존 로컬 카메라 Bind에서 확정한 실제 눈 창·아틀라스·깊이 매핑을 한 번만 연결한다. 다섯 눈 층과 월드 프레임 표식이 해당 프레임에 생산되면 기존 선택·합성 그래프가 이어진다.
- R25 crop, 202,752행의 커밋 버퍼, 선택기·후보·합성 커널 및 의존성이 필요하다. R24의 480×272/391,681행 구성으로 진행하면 실패한다. GPU 소유자 실패 코드, 유효 티켓, 셀당 중복·후단 쓰기를 확인한 뒤에만 원배율 PNG를 남긴다. 완료 증거가 확인된 자원만 기존 소유자가 정리한다.
- 눈 역할 후보가 없는 셀은 어떤 눈 연결 구간과도 점수를 공유하지 않는다. 따라서 기존 초기 선택과 같은 면적·대표 표본·동률 순서에서 고른 **같은 소스 주소**를 직접 출력한다. 눈 후보가 하나라도 있는 셀은 연결 구간 선택에 남는다. 256셀·1,024광선·2,048평가 상한은 유지한다. 실제 후보에 초과가 생기면 상태 코드로 실패한다.
- 이 폴더의 `.txt` 렌더 소스는 Unity가 자동 임포트하지 않는다. 앞서 사용한 R24 시험의 `cache`와 `build`가 필요하다. 여기에는 원본 모델 및 UV 지도 해시를 검증하는 `STATIC154.json`, `static/`, T2 방향 그림자 소스, `T3_PairedAperture154.compute.txt`가 들어 있어야 한다. 시험 러너의 `run`은 새 결과 폴더이며, 같은 폴더의 `T3_NativeAperture154.compute.txt`와 `CommonCellProducer.shader.txt`를 사용한다.
- GameMap1 실행에는 프로젝트의 실제 코드와 충돌하지 않는 승인된 시험 어댑터 연결이 추가로 필요하다. 현재 Git 변경이 있는 기존 EyeRenderer/EyeFeature/씬 경로에 이 시험 소스를 그대로 덮어쓰면 안 된다. 셰이더와 C#은 오프라인 컴파일됐고 이 커밋으로 Unity 실측이나 제품 활성화는 되지 않는다.

## 검증

`pwsh -File TestOwnerCore.ps1`은 Windows Visual Studio C++ 도구로 커밋된 컴퓨트 코드의 선택 코어를 그대로 컴파일하고 보관 후보의 C# 기준 결과와 비교한다. 원본 R24에서 얻은 전체 입력 교집합 정면 448·쿼터 498셀의 소유자, 표본 주소와 팔레트가 유지됐다. 연결 선택 도메인은 82·46셀이다. 역할 공유까지 감안한 독립 컴포넌트는 41+41, 23+23이며 별도 분할 실행 없이 기존 한도 안에 들었다. 이 데이터는 보관된 2×2 역할과 눈 광선의 교집합이다. 실제 1×1 장치 입력, 정면·쿼터 두 컷 및 자원 해제는 미검증이다.
