# 실제 이미지 검수

직접 연 파일: 5개 pose의 `*-phase-contact.png`, `neutral-template-colour-1x.png`, `neutral-template-colour-12x.png`.

- contact 위쪽의 기존 intrinsic allocator는 같은 pose에서 가로 두 셀·세로 두 셀·대각 두 셀 사이로 바뀐다. 아래쪽의 공동 배치는 템플릿의 홍채·흰자와 좌우 관계를 유지한 채 전체가 이동한다. 이 역할색 그림은 팔레트 미감 비교가 아니다.
- 중립 입력에서는 phase (0,0)의 ID2 홍채가 (217,52)/(218,52)이고, x만 0.0625셀 이동한 probe에서는 (218,52)/(218,53)이 된다. 개수는 둘 다 2지만 가로가 세로로 변한다. 이 사례는 `PHASE_FAILURES.json`의 실제 입력 packet/선택 좌표로 추적할 수 있다.
- 공동 배치의 실제 RGBA PNG에는 기존 Template216의 갈색·회색 홍채와 흰자색을 그대로 사용했다. 새 붉은 눈색이나 피부색을 칠하지 않았다. 해당 템플릿 색의 제작 의도까지 입증한 것은 아니다.
- 후보 RGBA는 투명한 분리 눈 레이어다. 피부/머리 위에 합성한 화면이나 현재 Unity 캡처로 표시하지 않았다. 검은 배경으로 보이는 PNG 뷰어 영역도 파일에서는 alpha0이다.
- 2× 원래 표시 크기와 12배 최근접 확대를 확인했다. 개별 셀 배치가 유지된 것은 확인했지만, 템플릿 모양 자체의 가독성·실제 pose 적합성이 최종 합격이라고 판정하지 않았다.

## 남은 정확한 범위

원본 표면 투영과 템플릿을 하나의 이동으로 맞출 때 각 눈 중심에 잔차가 생긴다. 현재 5pose에서 정수 snap 이전의 최대 거리는 약 0.49935 논리 셀이다. 이것은 snap 위치 오차(각 축 최대 0.5)와 별개다. 잔차를 감추기 위해 눈마다 독립 offset/확대/대칭을 넣지 않았다.

실제 가림·상안검·blink 기준 형태가 없어 그 부분은 해결하지 않았다. 미등록 50%/100% blink를 요청하면 열린 눈 형태를 반환하지 않는다. 같은 캐시 안의 등록 pose round-trip은 별도 검사했지만, 서로 다른 pose에서 같은 템플릿이 미술적으로 옳다는 뜻은 아니다.

이 결과가 해결한 것은 **동일 pose의 격자 위상만으로 특징 클러스터 내부 형태와 팔레트 family가 재선택되는 문제의 독립 경로**다. 연속 시간의 부드러운 위치 이동, 실제 눈꺼풀 변형, 최종 얼굴 합성까지 끝난 제품 수정은 아니다.
