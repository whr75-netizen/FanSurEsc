## 한 가지 고정 설계 후보와 기존 구조 연결

1. 입력은570의 같은 실행에서 저장한 실제 변형 폐곡선3개/94제어점과480×272 논리격자다. 원본 ring/arc 번호를 바꾸지 않는다. `NegativeRegion563.Branches566()`가 원본 cap/split/merge/mouth와 좌·우 원경계 경로를 제공한다.
2. **후보 정책:** 막힌 끝(cap)에서 시작해 연속 가로폭이 처음 한 격자 pitch에 이르는 지점까지만 음의 끝을 FILL한다. 나머지를 통째로 채우지 않는다. x/y 양 축에서 같은 정의를 사용하며 cap이 없는 구간은 이 정책으로 바꾸지 않는다. pitch=1은 논리픽셀 단위의 명시적 시제품 디자인 기준이다. 해상도에서 유일하게 도출되는 미적 최적값이나 논문 재현이라고 주장하지 않으며 계수 탐색은 하지 않았다.
3. FILL 부분은 source 경계 조각으로 닫은 양의 polygon으로 같은 폐영역 목록에 추가한다. `CurveArea511.Compute`의 원래 positive-winding 합집합이 한 번의 권위 있는 영역을 만든다. 원본 ring은 그대로 두므로 원본 arc ID가 유지되고, 새 ring은 원본 가지/양쪽 arc 경로/분할 좌표를 함께 기록한다. 새 ring의 일시적 배열 번호를 프레임간 의미 ID로 쓰지 않는다. 래스터 dilation/closing이나 최종 마스크 덧칠이 아니다.
4. 새 폐영역의 면적을 기존 `SelectRegions543`와566 그룹에 넣는다. 면적·경계 비용/가중치/히스토리는 바꾸지 않는다. 선택 뒤 `CapContract572.Finish`는 마스크를 수정하지 않고 실제 `KEEP_WITH_FILLED_CAP`/`FILL_BY_CAP_AND_SPATIAL_CUT`, 남은 셀, 입구 대응을 출력한다. 나머지까지 기존 공간 cut이 생략한 경우를 KEEP이라고 숨기지 않는다.
5. 원본 입구 선분이 실제로 교차하는 셀에서, 원본 가지 밖의 열린 배경으로 이어지는 **변 공유** 출구를 기록한다. 원래 진행축에 고정하지 않으며 근접 반경을 추가하지 않는다. 77의 원입구는 셀(234,43) 안에 있지만 아래 셀이 머리여서 오른쪽 변으로 출구가 옮겨진다. 축 방향만 허용한 첫 진단 판정은 잘못된 제약이었고, 셀의4변과 원본 가지 교차 관계로 바로잡았다. 선택 결과 자체는 재계산하지 않았다.

소유권은 양쪽 **원본 곡선 arc/제어망 경계**까지 전달된다. 이를 별도 의미의 가닥 중요도·재질·UV·동일시선 표면 증명이라고 부르지 않는다. 현재 구현은 작업 폴더/이 문서의 독립 시제품이며 `HeadCurve511.Areas511 → SelectRegions → runtime packet`에 아직 삽입하지 않았다.
