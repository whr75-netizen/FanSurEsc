# 538 — 경계 ID·소유권 연결, 전체 공간 평가 미진입

**평가용 중심 경로에 경계 ID와 변/안쪽 셀 소유권을 연결하는 오프라인 어댑터를 구현했습니다.** 43/50/44·8정상끝·접촉/구멍의13사례, 저장된 대조/후보35개에 같은 함수를 적용했습니다. 채움 마스크35개가 모두 그대로이고, 모든 원래 경계 변이 정확히 한 중심 노드에 전달됐습니다. 중심 경로로 fill을 재생성하지 않았습니다. 런타임 연결·선택기 교체·Unity·촬영은 없습니다.

## 실제 연결한 표현

`권위 있는 폐영역 → 방향 있는 경계 ID → 단위 변 → 안쪽 소유 셀 → 순서 있는 중심 노드`

각 노드는 경계 ID, 원래 변 인덱스, 논리 좌표(owner+0.5), 안쪽 셀을 보존합니다. 공유 픽셀은 하나의 무라벨 노드로 합치지 않고 경계별 노드와 복수 incidence로 기록합니다. 접촉의 퇴화 경로도 삭제하지 않습니다. ID는 같은 고정 포즈·후보의 입력에 속하며, 포즈 간 지속 대응을 구현했다고 주장하지 않습니다.

근사 전 참조 경계가 소유 셀을 통과하는 경우에는 참조 경계 ID·변 인덱스·선분 매개 구간도 전달했습니다. 이는 정확한 선분/셀 교차이고 가까운 색이나 임의 반경 검색이 아닙니다. **2D 경계 incidence가 같은3D surface/UV/depth/가림을 증명하는 것은 아닙니다.** 직접 교차가 없다는 사실도 해당 셀의 디자인이 틀렸다는 판정으로 사용하지 않았습니다.

## 연결 후 확인한 실제 대응 사건

| 포즈 | 원래 참조/출력 경계 수 | 작은 양의 참조 순환 면적 | 실제 결과 |
|---|---|---:|---|
| 43 | 2 / 1 | 0.0002608018셀² | 작은 순환의 셀(228,70)은 비선택, 직접 경계 carrier 없음 |
| 44 | 2 / 1 | 0.0002608612셀² | 같은 셀 비선택, 직접 carrier 없음 |
| 50 | 2 / 1 | 0.0002659395셀² | 한 출력 셀의 노드에 참조 경계0·1이 함께 대응 |

작은 순환과 주 경계의 선분 교차는 세 포즈 모두0입니다. 단순히 둘의 부위 이름이 같아서 같은 경계로 놓지 않았습니다. 50은 같은 픽셀에 서로 다른 원래 경계가 들어오는 경우이고,43/44는 작은 경계가 선택 결과에서 나타나지 않는 경우입니다. 이런 미세 영역의 생략/통합 자체를 사용자 요구 위반이나 새 버그로 세지 않습니다. 모든 소순환을 복구하는 것은 목표가 아닙니다.

정상끝8자료는 참조/출력 경계가1/1입니다. 접촉은 두 폐경계를 보존하되 중심 경로2개가 각각 단일점이고, 구멍은 경계2개·변16개·경계별 중심 노드12개를 유지하며 물리 픽셀4개를 공유합니다. 구멍은 채워지지 않았습니다.

## 전체 공간 항: 구현/미구현과 판단

| 항 | 이번 상태 |
|---|---|
| 방향 Eso | 원문과 같은 참조/출력 feature-line 분할·phase·퇴화/통합 규칙 미구현 |
| 위치 Esc | 고정된 원본 픽셀 선 대역·warp·가중 coverage 미구현. 영역 면적 A로 대체 안 함 |
| 폭 Eqs | 원문 벡터화·참조 perturbation 미구현.535 목록 제외를 재사용해 원문 구현이라고 하지 않음 |
| 계단 Eqj | 같은 픽셀 경로의 극값/span 및 고정 초기 분모 미구현 |

따라서35후보의 전체 점수는 모두 `null`입니다. 이 파일의 입력 검사는 점수 함수가 아니며, 빠진 항을0으로 둔 부분 합계도 계산하지 않았습니다. 논문 공간 가중치1/.5/1/.5는 명세만 유지하고 튜닝하지 않았습니다.

**동일 기준으로 두 결함을 개선하고 정상 특징을 보존했다는 근거가 아직 없어 런타임 선택 부분을 교체하지 않습니다.** 새 벌점·소실 경계 벌금·시간DP·일반 엔진은 만들지 않았습니다. 접촉/소실을 억지로 원래 선 구조에 맞추면 사용자가 허용한 픽셀 영역 생략/통합과 충돌할 수 있습니다.

남은 필수 전제는 후보와 독립적으로 고정된 **디자인 참조 경계 그래프와 선 대역**, 그리고 소실·통합·퇴화 시의 같은 평가 단위입니다. 원본 메시의 모든 미세 영역을 그대로 참조 선으로 요구하거나, 반대로 후보에서 참조를 다시 만들어 맞추는 것은 피해야 합니다. 이 정보가 없는 상태에서 항을 계속 추가하는 구현으로 넘어가지 않았습니다. 이것은 사용자에게 수작업을 요구하거나 기하 기반 영역 설계가 불가능하다는 결론이 아닙니다.
