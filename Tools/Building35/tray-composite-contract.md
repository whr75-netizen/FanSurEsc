# 실물 치수 바구니 합성 계약

입력은 원본 PerfectPixel 자동 정규화가 끝난 빈 상자와 독립 사과입니다. `tray-composite.py`는 새 이미지를 생성하거나 사과를 먼저 임의 저해상도로 축소하지 않습니다. 공통127 PPU의 최종 격자에 원본 색과 같은 표면의 XYZ를 한 번에 기록합니다.

상자 명세는 기존 `project_faces.py` 형식입니다. `.4×.3×.1m` 열린 상자의 **내부 바닥 Y=.015**와 테두리/벽을 구분해야 합니다. 내부 전체를 Y=.1의 닫힌 상판으로 지정하면 사과를 가리는 잘못된 원인이므로 거절합니다. source outline에 따라 물리 Y를 다시 이동하는 옵션도 허용하지 않습니다. 원본에서 가려진 내부 표면을 합성기가 창작하지 않습니다.

실물 치수의 권위 입력은 `metric-catalog.json`입니다. 폭W/깊이D/높이H/벽두께t/바닥높이f/사과 지름d를 읽어 명시한 상자 템플릿의 면 좌표를 치환합니다. 알 수 없는 템플릿 좌표는 거절합니다. 하단 행렬은 `nx=floor((W−2t)/d)`, `nz=floor((D−2t)/d)`이고 윗층은 `(nx−1)×(nz−1)`입니다. 현재 값은 지름.09m, 아래4×3/위3×2입니다. 첫층 중심은 X={-.135,-.045,.045,.135}, Z={-.09,0,.09}, Y=.06이며, 둘째층은 X={-.09,0,.09}, Z={-.045,.045}, Y=.06+sqrt(.09²−2×.045²)=.1236396103입니다. 구 중심 거리는.09m 이상이고 구가 실제 안쪽 벽 안에 들어가는지도 계산합니다. 최상단은.1686396103m이며 내용물 포함Collider는.4×.2×.3m입니다. 크기 변경으로 최소2×2배치/벽 포함/내용물 높이 조건을 위반하면 통합하지 않습니다.

원본 사과 alpha bbox를 포함하는 정사각 프레임을 .09m로 매핑해 비율을 유지합니다. 이 프레임은 최종11.43 texel입니다. 잎·꼭지가 포함되면 과육 지름을 따로 측정한 것은 아니며, 원본 모든 미세 픽셀이 살아남는다고 주장하지 않습니다. 구 투영 원 밖의 원본 불투명 픽셀은 버리지 않고 구 중심과 같은 D깊이의 실루엣 평면에 둡니다. 이 확장 픽셀 수와 최대 길이를 영수증에 명시합니다.

각 출력 광선에서 사과 깊이는 `C + R*sx + U*sy - D*sqrt(max(0,r²-sx²-sy²))`입니다. 상자와 사과18개 중 `dot(XYZ,D)`가 최소인 같은 표면이 RGB/alpha/XYZ를 소유합니다. Unity용 raw XYZ는 기존 규약대로 Y행을 뒤집습니다. 가림순서 강제 오버레이, 겹친 구, 구 경계에서 원본 잘라내기, 독립적인 depth fallback은 하지 않습니다.

출력 디렉터리는 `docs/artifacts/building35/tray-composite/render/`이며 `native.png`, `positions.rgba32f`, `owner-id.png`, `receipt.json`을 저장합니다. 부모 디렉터리에 `production-manifest.json`을 기록하고 asset ID는 `appletray_composite`입니다. 상자 원본 raster도 `render/crate-raster/`에 보존합니다. 이미 산출물이 있는 render 디렉터리는 덮어쓰지 않습니다. 실행과 Unity 통합은 `tray-composite-graph.json`이 담당합니다.

실제 실행은68×47픽셀/사과18개로 완료했습니다. Unity 기존 바구니3개에 공통 자산을 연결했으며, 원본·실패한 앞선 실험·다른23개 배치를 보존했습니다. 합성기의 receipt는 합성 단계의 증거이고, Unity 관찰과 기술 판정은 상위 폴더의 `play-observation.json`, `delivery-result.json`에 분리합니다. 원본 사과는 요구한11~13px보다 많은32px 프레임으로 검출됐으므로 최종 재표본화에서 원본 세부 보존은 보장하지 않습니다. PixelLab 정확한 해상도 재작화는 실행되지 않았습니다.
