# 587 GPU 면적 공급 후보 — 경계 반례 실패로 미채택

GPU 안에서 면적 A를 공급하는 후보를 실제 구현했고 저장 9개 포즈에서는 목표 출력 수000 / 000 / 111을 재현했다. 그러나 정확한 면적을 아는0.501셀² 반례에서 A=0.498291로 계산하여 N=0이 됐다. **품질 gate 실패이며 제품 채택 또는 전체 해결이 아니다.** 테스트한 소스·패치는 비실행 증거 폴더에 보존하고 원본 제품 소스5개를 최초 해시와 바이트 동일하게 복원했다. 이번 신규 소스2개와 이번에 생성된 메타2개만 백업 후 제거했다.

## 구현한 범위

기존 EyeFeature348 모델 바인딩과 원본 표면 draw를 재사용했다. 초기 모델/rest-head 자료에서 곡선 띠와 교차할 수 있는 삼각형을 보수적으로 찾고, 매 포즈 현재 변형 정점으로 적분 범위를 갱신한다. 정지 포즈의 A를 캐시하거나 프레임별 저장값을 주입하지 않았다. CPU는 이 범위와 자원만 준비한다.

별도 local shader variant는 기존 피부/흰자/홍채/아이라인/헤어/눈썹/몸 draw의 알파·깊이·눈 소속·곡선 띠 포함 여부를 기록한다. 적분 밀도는128/논리셀이며 SampleGrad 미분값은 기존4×4 텍스처 필터 폭을 유지하도록 변환한다. 현재 선택 HairMETA 및 원래 표면 깊이를 사용해 가림을 적용한다. GPU 부분 집계와 최종 집계의 A를 같은 command stream에서 기존 선택기에 넘긴다. **런타임 CPU readback은 없다.** 검증 스크립트의 GetData/ReadPixels는 제품 루프 밖의 진단이다.

`EyeArea587.cs`는 범위/RT 수명, `EyeRenderer367.cs`는 원본 draw와 집계 연결, `AreaSource587.hlsl`과 기존 source shader 두 개는 면적용 신호, `EyeFeature348.compute`는 집계와 A 교체, `EyeFeature348.cs`는 기본 OFF 옵션과 소유 자원을 담당했다. N=floor(A+.5), 후보 순위·홍채/흰자 소속·색 공급·최종 가림은 동시에 바꾸지 않았다. Source587 폴더와 PROTOTYPE_DIFF587.diff는 실제 테스트한 구현이며 현재 제품에 설치돼 있다는 뜻이 아니다.

초기 HLSL 예약어/루프 펼침 오류와 동적 색 셰이더 분기의 컴파일러 내부 오류를 수정했다. 최종 방식은 면적 전용 compile-time variant다. 최초 First587 자료의 A=0은 invalid kernel 결과여서 성공 근거에서 제외했다. 컴파일 성공만으로 통과하지 않고 수정 후 실제 GPU 출력을 검사했다.

## 저장 포즈 검증

같은 Walk 포즈·카메라·저장된 127.0~150.856도 입력·해상도·고정 시각 조건으로 9개 OFF/ON 쌍을 실제 재생성했다. 이는 **고정 저장 포즈 검증**이며 실제 연속 회전 검증을 대체하지 않는다. 첫 유효 한 쌍을 재촬영하지 않고 남은 8쌍만 추가했다.

OFF visible/intrinsic은 이전 저장 기록과 모두 같았고 ON/OFF intrinsic 차이도0이었다. 흰자 feature 변화1셀은 잘못 선택된 속눈썹 해제로 기존 흰자가 드러난 경우다. 새 홍채/흰자 소실은 없었다. ROI의 색/소유권 변화는 면적 수량 변화가 만든 세 위치에 연결된다. 이 결과를 전신 색·모든 방향·시간 품질 통과로 확대하지 않는다.

## 결정적 반례와 누락 정보

원본을 보존한 두 삼각형 평면 위에 같은 포물선 띠를 정의했다. u 폭2.16과 띠 높이0.58, 투영 배율s에서 참조 넓이는 `2.16×0.58×s²`다. 불투명 표면이라 복잡한 알파 필터 차이가 원인이 될 수 없다.

- 목표 A=0.501에서 GPU A=0.498291015625 → N=floor(0.998291015625)=0이며 기대 수량은1이다.
- 교차64분할 추정 E=0.00146484375에서 A+E=0.499755859375라, 임계값과 분리됐다는 판정조차 잘못됐다. 실제 편향 약0.002709가 E보다 컸다.
- 목표0.49에서도 실제 오차 약0.003184가 추정 E=0.000488보다 컸다. 교차 표본 간 일치가 체계적인 경계 손실을 검출하지 못한다.
- 정상 축소0.65/0.55/0.45/0.35는 N=1100, 완전 가림과 면적0은0으로 나왔다. 이는 경계 실패를 상쇄하지 않는다.

원본 곡선/삼각형은 연속인데 현재 신호는 각 미세 래스터 중심의 band 여부0/1만 보존한다. 경계 픽셀의 일부만 차지하는 면적은 집계 전에 잃는다. 따라서 다른 임계값/고정 최소1픽셀/이전 프레임 고정으로 덮지 않았다. 단순히128을 더 큰 상수로 바꾸는 구현도 추가하지 않았다.

필요한 다음 입력은 투영 삼각형 경계와 원본 곡선 띠의 **부분 커버리지**, 그리고 그 부분에서 실제 앞 표면이 차지하는 소유권이다. 이 정보를 공급하지 않은 채 binary texture를 더 집계하면 정확도 계약을 보장할 수 없다. 삼각형별 면적을 중복 합산하거나 뒤 가림 면적을 더하는 대안도 허용하지 않는다. 새 엔진/다른 비용항/시간 필터는 시작하지 않았다.

추가16개 이동은1/16셀 간격으로128 래스터와 정렬돼 있다. 출력이 같았지만 미세 격자 위상 변화에 대한 독립 안정성 증거로 세지 않는다. 반례 전체 입력과 실제 수치는 COUNTERS587.tsv에 보존했다.

## 비용과 측정 한계

고정 포즈에서3쌍 워밍업 후 OFF/ON5쌍과 준비 함수5회를 wall clock으로 측정했다. 준비 CPU 중앙값0.209ms, p95 0.365ms였다. 전체 RenderFrame 호출 중앙값은 OFF624.75ms/ON613.54ms, p95는820.25/857.24ms였다. 변동이 커서 개선이나 GPU 추가 비용을 판정할 근거가 아니다. 기존 파이프라인의 대기·readback을 포함하며 테스트 파일 쓰기/새 캡처는 제외했다. Player FPS 또는 기존42.48ms 옷 단계와 비교하지 않는다.

추가 텍스처의 논리 할당은 해당 EyeFeature 인스턴스에서188,088,320B, 약179.4MiB였다. 드라이버 상주 메모리나 전체 앱 메모리가 아니다. 워밍업 후 OFF/ON 측정은 캐시된 RT를 보유한 상태이며 기본 OFF 최초 실행에서 이 RT가 생성된다는 뜻은 아니다. 후보 제거와 Play 종료 후 자원은 해제했다.

**관리 할당량과 GPU 시간은 미측정이다.** 기존545의 raw GC.Alloc 양성 대조 경로를 시도했으나 첫 batch와 한 번의 프레임별 수정 모두 원시 스코프를 받지 못했다. GPU recorder도 유효한 비영 샘플 수를 얻지 못했다. 기록의0바이트/0ns를 실제0으로 해석하지 않는다. 제한15/60초 후 자동 복원했고 추가 재시도는 하지 않았다.

## 현재 상태와 미실행

제품 소스는 원본5개 해시와 정확히 같고 신규2개 source/meta는 비실행 기록으로 격리했다. 직접 확인에서 Edit clean, 기존 두 옵션/Head/Clothes/자동 입력 OFF, inputBytes0, captureDelta0, backgroundfalse, profilerfalse, 현재 shader 오류0이다. 사용자 QualitySettings/TimeManager 해시는 같다.

경계 반례 gate 실패로 실제 인접 회전·세 방향 회귀·새 전신 GIF는 실행하지 않았다. 메인.html의 영상은 기존583 비교이며 새 개선 결과로 표시하지 않는다. 기존 홍채24/속눈썹846/세 방향1,136 증거는 원본 소스 복원으로 보존한 것이며 새 회귀가 아니다. 내부선 팔레트3, 손 문제, 일반 실행 성능은 별도 미해결이다. P드라이브와 Library403 재시도, 대량 원시 버퍼 생성은 없다.
